# ZCard v1.2.124

发布日期：2026-11-23

## 上游商品定位与人工拿货

- 商品列表和采购列表提供明确的“打开上游商品”入口；采购详情集中展示原渠道、商品编号、规格编号、上游单号和原请求号，编号可复制，手机端同样可操作。
- 销售订单按每件商品分别展示来源，不再将多件商品合并为一个上游渠道。下单时保存来源，实际卡密采购时另存采购来源；有采购记录时优先显示实际采购来源。
- 历史快照保留原渠道名称、网站、商品及规格链接。之后换绑商品、修改渠道或删除渠道，不会使已保存的来源跳到新商品。旧采购单仅用原连接和原商品编码恢复，并标明按当前渠道推算；缺少历史记录时明确提示无法确认，不套用当前商品绑定。
- ZCard 和萌次元使用已核实的商品路由。萌次元组合编码拆分为原商品和规格，其他未确认路由的渠道提供网站入口与原编号，不猜测商品链接。
- 渠道可配置独立网站地址和商品链接模板，兼容原有 {base}、{code}，新增 {product_id}、{sku_id}。链接编码并清理凭据；配置变化只影响之后保存的来源。
- 打开链接只用于核对，不会自动下单。采购结果不明确时先查原上游订单或原请求号，避免重复拿货。原有查询恢复与人工补发流程保留。
- 来源信息仅对后台管理接口开放，不出现在买家订单或对外供货接口。

## 升级说明

本版为 SQLite、MySQL、PostgreSQL 各新增一项迁移，只给订单项及采购单增加可空的来源快照列，不回填或改写历史商品绑定。升级前备份数据库、配置和上传文件，保留原加密密钥，配套更新服务端、后台及内置商城后重启。

没有商品直达链接的渠道可在“渠道管理 → 货源渠道”配置网站地址与模板；历史订单没有记录的来源无法凭空恢复。新版不会自动重买、退款或处理此前待核对的采购单。

提供 Linux amd64 / arm64 完整程序、SHA256 校验、ED25519 签名更新清单及双架构 Docker 应用和配套更新器。发布不代表客户生产站点已升级，真实供应商交易仍需分别核对。
