# ZCard v1.2.110

发布日期：2026-10-03

## 短信接码购买修复

- 修复短信渠道报价成功后，购买请求因价格上限 `max_supply_amount_cents` 被发送为字符串而遭供货接口 `400 CODEC` 拒绝，订单持续显示“采购确认中”或最终进入“待人工核对”的问题。
- 普通短信商品与短信渠道商品的购买金额统一按 JSON 整数发送，保留整数精度、最终请求体签名、原购买意图与幂等键。历史意图中的金额字符串和整数继续兼容。
- 对明确的 `400 CODEC` 请求解析错误停止无效自动重试，转入人工核对并显示 `upstream_codec_error` 诊断；网络异常、限流和其他结果不明确的错误继续按原规则处理。

## 旧订单核对与恢复

升级不会自动恢复已经进入“待人工核对”的旧任务。请先核对原供货订单、扣款及退款结果，再在后台接码诊断中填写核对说明并使用“恢复原任务”；恢复沿用已保存的购买意图和幂等键。

上游已经受理的原请求会重放原回执并继续同步会话。此前未受理且原报价已失效的请求，可能返回明确的未扣款拒单回执，再由现有退款协调流程处理买家实际支付金额。升级或恢复任务不保证旧订单能直接取到号码，取号、收码及退款均需按实际结果核对。

## 升级与验证

本版无新增数据库迁移。请备份数据库、配置和上传文件，保留原加密密钥，更新完整发行包并重启服务端。从旧版本升级仍需执行已有累积迁移。发起短信采购的站点需升级，无需删除货源、商品映射或历史订单。

回归覆盖普通与渠道购买的 HTTP 请求绑定、最终请求体签名、大整数精度、历史意图读取兼容，以及 `400 CODEC` 诊断、停止自动重试和资金状态保持。相关适配器测试、静态检查和购买契约竞态检查通过；真实供应商付费取号、实际收码、退款到账及客户站点升级仍需分别验收。

发行包提供 Linux amd64 / arm64、SHA256 校验和、ED25519 签名清单及 Docker 镜像，继续支持 Docker 后台在线更新。版本发布不代表客户站点已自动升级。
