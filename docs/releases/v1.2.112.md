# ZCard v1.2.112

发布日期：2026-10-25

## 按规格导入与管理卡密

- 后台「卡密库存」支持选择商品与目标规格后预览、去重并导入；商品和规格页面增加「导入卡密」入口。有规格商品必须明确选择规格，无规格商品继续使用商品默认池。
- 卡密列表、靓号列表和导出支持按规格筛选；可分别查看全部、默认池与具体规格。库存目标信息使用独立库存权限，无需授予商品成本等管理权限。
- 导入批次保存导入时的目标规格和名称，同时展示卡密当前分布；导入预览与确认核对商品版本，配置变化后须重新预览。实体、人工交付、重复发货、上游采购等不适用目标会显示原因，避免误导入。

## 历史库存归属与批次保护

- 历史默认池卡密可按所选卡密或原导入批次预览，再分配到同一商品的具体规格。单次最多 10000 张，仅处理可用且未被占用的默认池卡密，排除预占、已用、会员锁定及抽奖发放引用。
- 确认归属使用预览中固定的卡密 ID，并在事务中重新检查状态；发生冲突时整次回滚。归属保留原导入批次、原始批次统计和导入目标记录。
- 撤销批次前展示所有当前规格的分布。确认撤销作用于整个原始批次的剩余可用卡密，保留预占、已用和禁用卡密；预览后库存变化会要求重新预览。
- 规格存在可用、预占或禁用卡密、订单、启用中的抽奖奖品或当前及待确认发货来源时，阻止删除，避免库存或履约引用失去归属。

## 库存消费与日志保护

- 有规格商品的可售卡密库存仅统计有效规格池，默认池和已删除规格的遗留库存不再虚增可售数量；保留人工共享配额、重复发货及上游库存的既有语义。
- 内置商城积分兑换遇到多规格商品时进入商品详情选择规格；各规格按自身库存下单和发货，某规格售罄不会取用另一规格的卡密。
- 原生旧版供货、ACG 和独角数卡兼容接口暂不支持多规格新单：目录隐藏多规格商品，直接请求在扣款前拒绝；已有订单的查询及幂等重放继续返回原回执。
- 导入卡密、预览样例和自由文本请求标识不写入操作审计或 Kratos 运行日志；日志仅保留必要标识、数量等元数据。

## 升级与验证

本版新增 SQLite、MySQL、PostgreSQL 的 `card_imports` 目标规格字段迁移。请先备份数据库、配置和上传文件，保留原加密密钥，更新完整发行包并重启服务端，确认启动迁移成功后刷新后台与商城。前后端需配套更新。

旧批次的目标保持「历史未记录」，不会自动补写为默认池或具体规格；新批次明确记录默认池或所选规格。历史卡密、加密内容和批次来源保持原样，已有规格商品的默认池库存需在后台人工预览并归属后才作为对应规格库存销售。无规格商品继续使用默认池；旧导入客户端对有规格商品必须补传 `sku_id`，否则会收到明确错误。

独立第三方主题不随主程序更新。使用积分兑换或其他直接下单入口的主题需确保提交用户选择的规格，客户站点升级后应核对主题与实际购买流程。

本地全量后端测试、相关并发竞态检测、前后台类型检查与生产构建、1440px 桌面和 390px 手机浏览器回归已通过。真实 MySQL、PostgreSQL 验证了多规格导入、混合规格下单与对应卡密履约、规格售罄隔离，以及锁等待后的当前状态检查；从 v1.2.111 升级的隔离 HTTP 验收覆盖旧批次、筛选、导出、归属、整批撤销、权限、审计与重建持久化。

客户生产站点的升级、第三方主题及真实交易结果需分别验收；频道公告由用户手动发送。
