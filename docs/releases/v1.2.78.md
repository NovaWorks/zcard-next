# ZCard v1.2.78

发布日期：2026-09-24

## 支付与取货体验

- 收银台显示当前可用余额；余额不足时提示差额并禁用余额支付，提供充值或其他支付方式入口。余额读取失败可重试，后端余额不足错误改为清晰提示，并保留实际扣款时的余额校验。
- 后台可设置支付渠道显示顺序，并调整渠道内支付方式的前后顺序；同排序值按稳定顺序展示。
- 修复未付款或尚未交付的订单点击取货后出现空白页的问题，兼容接口省略空交付列表，并保留继续付款入口。
- BEpusdt 增加响应格式异常与网关拒单错误码的区分，方便排查接口、钱包、限额和回调配置；不记录密钥、签名或原始敏感响应。本轮没有更换固定模式协议，也不将尚未验证的现场 USDT 拒单宣称为已解决。

## 采购异常与人工补发

- 上游卡密先加密保存；买家交付记录、采购完成状态及采购成功事件在同一事务内提交。写入失败不再显示采购已完成，可用已保存卡密恢复本地交付，不会重新向上游购买。
- 旧的“采购已完成、买家未收到”记录可重试交付；需要换卡或部分补发时，核实上游后可转人工。退款处理中、已退款、已足额交付的订单继续受状态校验保护。
- 采购列表增加客户订单号及精确搜索，订单详情可直达关联采购单。人工补发弹窗展示所选商品的采购状态，支持重试已有卡密交付或核实后转人工，显示具体失败原因。
- 采购主表与明细原子建单，避免建了一半。采购准备失败尽量立即建立待人工记录；巡检补查付款超过五分钟但未生成采购任务的订单，并将停滞、无上游单号的采购转人工核实，不盲目重购。历史缺失任务在下一次巡检后可见。
- 完整交付、部分交付、重复回调及并发人工处理分别校验，避免少发被当成成功或重复出卡。

## Telegram 商家订单通知

- 系统设置新增 Telegram 主站商家订单通知，可配置 Bot Token、接收人或管理群 Chat ID，以及新订单、付款成功、发货完成、退款成功事件。默认事件为付款成功，需管理员配置并启用。
- 按事件与接收目标持久化、去重投递，支持失败重试、限流退避、重启恢复和单目标手动重试；后台可查看发送记录并主动发送测试消息。
- Bot Token 加密保存、回显掩码并在审计中脱敏；订单通知不包含卡密、查询密码或支付密钥。升级前的历史订单不会自动补发通知。

## 本版包含的近期更新

此前 v1.2.75—v1.2.77 已发布的上游账号报价、商品独立加价同步、导入预览成本修复，以及 BEpusdt 多链收银台与 GM Pay 独立渠道支持，均随本版保留。旧商品缺少独立加价规则时仍按 v1.2.75 的升级说明处理；BEpusdt 实际可选币种与网络以网关钱包、汇率及启用状态为准。

## 升级说明

本版新增 Telegram 投递记录的 SQLite / MySQL / PostgreSQL 增量迁移。升级前备份数据库、配置与上传文件，首次启动确认迁移完成；后台和内置商城需一起更新。独立第三方主题需另外适配余额及取货交互。

旧异常采购可在“渠道管理 → 采购单”按完整客户订单号查找，优先点击“重试交付”；需要人工换卡时先核实上游扣款和出货结果，再转人工补发。系统不会替管理员向上游重新下单。

已完成 Go 全量测试、后台类型检查及构建、桌面/手机浏览器回归，以及 SQLite、MySQL、PostgreSQL 的交付故障恢复与并发防重复验证。Telegram 使用隔离接口测试；真实通知投递、真实链上付款及具体线上异常订单，仍由部署后联调验收。

Linux amd64 / arm64 完整发行包内置后台与商城，附 SHA256 校验和 ED25519 签名更新清单。Docker 用户可使用 `ZCARD_VERSION=v1.2.78 bash deploy/docker-install.sh` 更新。上传发行包不代表客户服务器已经升级，频道公告由用户手动发送。
