# ZCard v1.2.83

发布日期：2026-09-26（北京时间）

## 商城首屏与主题修复

- 修复刷新时先显示默认蓝色、默认页脚，再切换到自定义内容的问题。主题颜色和公开配置随 HTML 下发，页脚不再等待购物车或登录请求。
- 通用构建不再把构建时的 `fetch failed`、空分类和默认店铺内容写入正式页面，改为中性的加载状态；脚本加载失败时保留刷新入口。
- 合并配置请求，数据库批量读取公开设置；读取失败不再把默认值当作成功配置覆盖已有外观。新发布的配色、清空的内容和恢复默认能正确替换旧值，主题预览保持独立。
- 商品与分类分别显示加载、失败和真实空结果，电脑及手机均可单独重试。慢横幅不阻塞商品目录；闲置后返回或网络恢复时按需刷新，减少重复请求并保留浏览筛选。
- 配置与目录只读请求设置有限超时和最多一次自动重试，下单等写入不自动重试。保留会员身份与价格；购物车、验证码和交易设置仍读取最新配置，外观加载不受其阻塞。
- 补齐手机分类失败入口、清空页脚后残留内容、初始站点图标，以及重新读取配置重复弹出维护提示等边界。

## 工单 / TG订单通知

- 将 TG 通知从邮件短信区域移入“工单 / TG订单通知”，集中管理通知开关、Bot Token、接收位置、事件、测试及发送记录。
- 每个接收位置支持 Chat ID 和可选 Topic ID，可将订单通知发到 Telegram 群组的指定话题；未使用话题时留空，沿用默认接收位置。
- 支持多个接收位置，校验 Chat ID、Topic ID 和重复配置；兼容原有配置与已保存的 Token，保存时不要求重复填写 Token。
- 可对已保存的位置发送测试消息，区分“已排队”和“已送达”；发送记录显示话题及失败原因，重试沿用原接收位置，不随新设置改变目标。
- 完善权限、无效话题及限流等错误处理；话题发送失败不会改投默认位置。测试消息不包含卡密或查询密码，错误信息隐藏 Bot Token。

## 升级说明

本版无新增数据库迁移；从更早版本升级仍会执行未应用的历史迁移。升级前备份数据库、配置及上传文件，使用完整包同步更新服务端、后台与商城，完成后刷新浏览器。

主题首屏修复主要针对内置 Classic 商城。独立安装的第三方主题如包含自己的旧加载逻辑，需更新对应主题包。Topic ID 仅适用于支持话题的接收目标，机器人必须拥有发送权限；消息已排队不代表已送达，网络结果不明确时重试可能重复，请先查看目标话题。

本地验证覆盖前后台类型检查与生产构建、后端全量测试、通知/设置/主题竞态测试、fullstack 集成、金额回归、首屏配置回归，以及电脑/手机慢请求、503、脚本失败及重试恢复。TG 发送测试使用模拟接口，客户实际群组仍需升级后测试。仓库历史格式与开源路径 CI 问题不属于本版修复范围。

发行包提供 Linux amd64 / arm64、SHA256 校验和 ED25519 签名更新清单。版本发布不代表客户站点已经升级。Docker 用户可使用 `ZCARD_VERSION=v1.2.83 bash deploy/docker-install.sh` 更新。
