# ZCard v1.2.80

发布日期：2026-09-25

## 大批量商品导入修复

- 修复整批商品共用报价、库存超时额度，导致前面少量商品成功、后续大量商品连续失败的问题。每件商品分别处理报价、保存和库存查询，临时故障按阶段有限重试。
- 导入改为可恢复的后台任务，提交后立即显示进度；关闭页面不影响执行，重新进入货源的「任务」入口可继续查看。任务和商品处理结果保存到数据库，无需启用 Redis。
- 商品、规格、映射与处理检查点一起保存，服务异常重启后从未完成阶段继续，避免重复创建已成功商品。重复提交同一次请求会返回原任务。

## 失败处理与操作体验

- 分别展示已保存、导入失败、跳过和库存待确认情况，库存查询失败不再重复计作商品导入失败。
- 支持停止、继续、重试失败商品和仅重试失败库存。停止保留成功结果；库存单独重试不会重新导入商品，也不会继续已停止的其他商品。
- 遇到上游限流时等待后再尝试；账号认证或访问拒绝时暂停任务，提示检查配置，避免持续请求并批量报错。
- 网络断开时显示重新连接提示，不再反复弹出报错。电脑使用明细表格，手机使用商品卡片，任务入口集中显示进度和可用操作。

## 数据与商品保护

- 保存前重新检查商品锁定和人工修改，发生冲突时跳过，避免导入覆盖运营人员的修改。
- 货源账号、定价、汇率或分类映射变化时暂停任务，确认当前配置后再继续；已有商品的库存重试仍只处理库存。
- 新导入商品在库存确认前保持下架；待定价或不可售商品不会提前上架。原有商品的下架状态继续保留。
- 同一货源的维护任务串行执行；存在待执行或正在执行的任务时阻止删除货源。正常采购下单不加入维护任务队列。

## 升级说明

本版包含 SQLite / MySQL / PostgreSQL 数据库迁移，新增导入任务明细和任务恢复字段。升级前备份数据库、配置及上传文件；SQLite 迁移会重建相关表并保留历史数据，建议在低峰期升级并检查迁移日志。

后台与服务端须一起更新。完整 Linux amd64 / arm64 发行包已内置后台和商城，升级后刷新浏览器；自行调用导入接口的客户端需适配返回的 `task` 和任务进度查询，不能再将提交响应视为整批导入完成。

旧版失败导入不会自动转成新任务，升级后请重新选择未成功的商品；已保存但库存异常的商品优先使用「仅同步库存」或重试失败库存。上游账号、权限或报价本身存在的问题仍需按任务提示处理。异常退出后的任务恢复需要等待旧执行租约过期，最长约 120 秒后由扫描器接续。

已完成后端全量测试、货源模块竞态检测、三种数据库迁移与恢复测试、后台类型检查和构建，以及电脑和手机浏览器导入流程回归。测试使用隔离环境，不代表客户服务器已经升级。

发行包附 SHA256 校验和 ED25519 签名更新清单。Docker 用户可使用 `ZCARD_VERSION=v1.2.80 bash deploy/docker-install.sh` 更新。
