# ZCard v1.2.102

发布日期：2026-10-01

## 支付宝配置与支付处理修复

- 应用私钥与支付宝公钥改用多行输入，支持裸 Base64、完整 PEM、PKCS1 / PKCS8 私钥，以及粘贴时产生的转义换行；已保存密钥不回显，留空保留原配置。
- 修正请求签名参数和支付宝时间格式，完善通知的应用、订单、金额及 RSA2 签名检查，成功通知返回支付宝要求的纯文本确认。
- 主动查询校验支付宝响应签名与订单信息；异步通知未到达时可按商户订单号核对支付结果，兼容已有商品订单和充值订单。
- 本次继续使用支付宝公钥模式，证书模式需另行适配；配置仍须填写正确的应用私钥与支付宝公钥。

## 空分类及商品删除修复

- 分类删除与商品计数采用相同口径，已删除商品的历史分类引用不再阻挡空分类删除；清理旧引用、分类运营设置、供货分类定价和货源分类映射。
- 区分仍有子分类、仍有商品、分类不存在和服务异常，显示具体原因；隐藏、下架商品仍算有效商品，未选中的子分类继续保留。
- 上架、隐藏、下架商品均可直接删除，立即从后台、商城和供货目录移除，释放分类，关闭自动上下架并清理购物车、分类运营设置、货源映射和供货专属价。
- 默认保留历史商品归档、订单、已交付卡密和取货内容；未售卡密转为停用，不再销售。实体商品历史订单及退货库存记录继续保留。
- 锁定商品、进行中的订单或退款、被订单占用的卡密、未完成采购及在用抽奖活动继续阻止删除，并显示处理原因。另选删除关联订单仍需核对商品名和订单数量，符合原有保护条件后才执行。
- 供货详情和定价拒绝已删除商品，供货下单与删除共用商品行锁；上游同步不会恢复归档商品。历史供货订单重试继续返回原交付记录，不重复扣款。
- 批量删除按顺序提交，避免 SQLite 写锁竞争，保留失败项供重试；单个或批量删除后同步刷新商品列表和分类信息。

## 供货账号充值修复

- 修复充值提交字段与接口不一致导致的 `missing required field: amount_cents`。界面输入元，提交整数分，例如 30 元提交 3000 分。
- 每笔充值使用独立标识，同一账号可多次充值相同金额；同一次请求的失败重试沿用原标识，已入账请求重试返回成功，不重复增加余额或流水。
- 相同标识修改充值金额会被拒绝；补充正数、精度和单笔金额上限校验，提交期间阻止重复操作和更换充值账号。

## 升级说明

本版无新增数据库迁移。请备份数据库、配置及上传文件，保留原加密密钥，使用完整发行包同步更新服务端与内置后台、商城，并刷新浏览器。从旧版本升级仍需执行已有累积迁移。

支付宝配置使用应用私钥与支付宝公钥，已配置密钥无需重复填写；此前已删除商品关联的空分类，升级后可重新尝试删除。进行中的业务需先处理完成，再删除对应商品。

验证覆盖 Go 全量测试、受影响模块 `go vet`、支付宝及分类、删除、充值的 race 回归、后台类型检查与生产构建、fullstack 内嵌资源检查，以及 390px / 1440px 页面回归。页面测试覆盖金额换算、失败重试、相同金额的独立充值、商品删除、批量失败项保留及分类刷新。接口与模拟页面测试不代表商户真实支付宝交易或客户生产站点已验收。

发行包提供 Linux amd64 / arm64、SHA256 校验和、ED25519 签名清单及 Docker 镜像，继续支持 Docker 后台在线更新。版本发布不代表客户站点已自动升级。
