# ZCard v1.2.91

发布日期：2026-09-30（北京时间）

## 新增实体商品与快递配送

- 新建商品可选择虚拟或实体；实体支持包邮或固定运费，支持商品及规格数量库存。
- 虚拟与实体商品可混合下单；包含实体商品时填写收货人、电话、国家、地区、详细地址及邮编，国家联动一级地区，省州及邮编按目的地规则校验。
- 服务端重新核算商品与运费，保存价格和地址快照；相同商品的多个数量或规格每单只收一次固定运费，不同商品运费相加。
- 后台新增配送状态筛选、填写快递公司与单号发货、包裹收货确认、地址及物流更正；前台与游客查询页展示配送进度。
- 支持按不同商品项分包发货；每个商品项一次寄出全部剩余数量。取消未发货数量归还库存，已寄出商品需验收入库后单独补库存。

## 商品退款与订单一致性

- 后台支持分别登记商品、运费、支付手续费退款和取消数量，展示退款凭证、原因及逐项分摊记录。
- 余额退款实际入账；外部支付退款需先在渠道核实退款成功，再登记凭证。同一订单禁止重复登记同一外部退款凭证。
- 运费不参与积分、推广佣金和分站利润；商品退款按累计实际金额扣回奖励，补齐多次部分提现与并发退款保护。
- 修复混合订单取消后仍交付卡密、延迟支付事件发起采购、全单取消误发交付通知等问题；上游采购结果不明时需先核对，不能直接退款。
- 订单详情与交付查询共用查询密码失败锁，验证买家及租户归属；补充电话号码、实体卡密导入及库存结构变更限制。

## 升级说明

本版包含 SQLite / MySQL / PostgreSQL 增量数据库迁移。升级前备份数据库、配置与上传文件，使用完整发行包同步更新服务端、后台与商城，检查迁移日志并刷新浏览器。自定义主题需适配实体商品地址、运费报价及物流查询接口后再开放实体商品销售。

已有商品及旧订单保持虚拟和原交易口径；商品类型保存后不可切换。已有无规格历史订单的实体商品若需改为规格销售，应新建商品，避免取消或退货回库位置变化。已经产生实体订单后，不应直接回滚至不识别实体商品的旧程序。

首版提供国家与一级地区联动，不包含全球城市区县下拉、重量运费模板、同一商品项拆包、自动快递轨迹或自动原路退款。收货国家须在商品配置的可配送范围内。

验证通过后端全量测试、相关模块竞态检测、真实 MySQL / PostgreSQL 的迁移与库存/发货/退款/提现并发测试、前后台类型检查及生产构建，以及独立数据库的浏览器下单、发货、收货和退款记录展示验收。测试不代表真实支付、快递及消息渠道已经联调。

发行包提供 Linux amd64 / arm64、SHA256 校验和 ED25519 签名更新清单。Docker 用户可使用 `ZCARD_VERSION=v1.2.91 bash deploy/docker-install.sh` 更新。版本发布不代表客户站点已经安装或重启。
