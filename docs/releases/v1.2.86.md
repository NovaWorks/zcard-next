# ZCard v1.2.86

发布日期：2026-09-27（北京时间）

## 低库存加速检查

- 货源连接的定时计划新增独立的低库存加速开关，可自定义库存数量和检查间隔；默认库存不超过 10 件时，每 5 分钟检查一次，间隔支持 5–1440 分钟。
- 按实际由上游发货的商品规格检查，包含零库存和自动因缺货下架的商品；本地卡密、重复发货、锁定商品、人工下架和停用货源分别处理。
- 与常规采集、调价和执行时间窗独立；优先检查已知低库存，多货源轮转，长时间导入不会占用库存检查任务锁。
- 查询失败保留上次成功库存供参考，并退避重试；限流会延后执行，旧请求不能覆盖更新的库存结果。
- 常规同步及下单校验取得的规格库存同步更新缓存，后台展示最近检查时间和运行结果。

## 后台库存预警

- 系统设置 → 货源新增库存预警开关；“库存低于此数量时提醒”可由后台设置，默认低于 5 件提醒，与加速检查阈值独立。
- 商品列表与预警筛选按具体规格及实际发货来源判断，展示触发预警的规格，不再用总库存或固定 10 件颜色规则掩盖规格缺货。
- 未知、过期和无限库存不误报为缺货；完善手机端配置布局和输入校验。

## Telegram 低库存通知

- 系统设置 → 工单 / TG通知新增独立的主站低库存通知开关，默认关闭；关闭订单通知仍可接收库存通知。
- 复用 Bot Token、Chat ID 和可选 Topic ID，支持多接收位置、配置测试、发送记录和失败重试。
- 首次确认低库存合并提醒，持续低库存不重复发送；降至零可追加一次售罄提醒，确认恢复后再次跌破受 30 分钟冷却限制。
- 提醒状态和待发送记录在同一事务保存，处理多实例并发与重启去重；关闭通知或更改阈值后跳过旧配置下尚未发送的通知。

## 升级说明

本版包含 SQLite / MySQL / PostgreSQL 数据库迁移。请先备份数据库、配置和上传文件，使用完整发行包同步更新服务端、后台与商城，检查迁移日志并刷新浏览器。确保 worker/all 进程运行，以执行后台定时任务。

升级后低库存加速检查和 TG 库存通知默认关闭，需要分别开启。库存预警默认开启，已有提醒阈值保留。普通库存仍由常规同步发现变化；限流、失败退避或大量待检查商品可能延后检查，5 分钟为目标周期，不能保证上游在付款期间仍有货，既有下单库存校验继续保留。

验证覆盖 Go 全量测试、库存与通知竞态测试、SQLite 旧数据升级、真实 MySQL / PostgreSQL 并发回归、后台类型检查及生产构建，以及电脑与手机配置保存流程。界面使用隔离接口，未采购真实商品或向真实 TG 发送测试消息。

发行包提供 Linux amd64 / arm64、SHA256 校验和 ED25519 签名更新清单。发布不代表客户站点已经升级。
