# ZCard v1.2.82

发布日期：2026-09-25

## 慢上游目录与分类导入修复

- 商品目录改为后台加载，页面显示进度与重试入口，关闭页面不打断任务；任务、目录快照和恢复状态保存到数据库，无需 Redis。
- 只读目录请求超时延长至 120 秒，临时网络故障最多重试一次，整个目录任务上限 5 分钟。采购下单继续使用原有超时和重试规则。
- 完整目录快照有效期 2 小时，提交导入和展开核价复用当前快照，避免反复拉取大目录；刷新或加载失败保留商品选择、分类草稿及定价设置。
- 修复中文、表情分类名按字节校验导致保存失败的问题，分类名称统一限制为 1–100 个字符；提交前标明具体出错分类。
- 补齐并发加载去重、进程重启恢复、过期任务写入隔离，以及货源账号变化后的快照失效保护。

## 库存筛选与补货检查

- 商品管理拆分“上架状态”和“库存状态”两组筛选，可组合查询“已下架 + 有库存”“已上架 + 无库存”，并叠加分类、货源、锁定及自动管理状态。
- 新增“补货待上架”，集中查看已观察到从缺货转为有货、当前仍下架的商品。历史缺货记录不足的商品可使用“已下架 + 有库存”查找。
- 库存过期或查询失败显示“待确认”，不再与确认无库存混为一类。列表使用实际发货来源的缓存，筛选在服务端分页前完成。
- 选择货源后可发起后台库存与补货检查，完成后刷新列表；离开页面后任务继续执行。

## 可选自动上下架

- 支持单件或批量开启、暂停自动管理；默认关闭，不改变历史商品的管理方式。开启后约每 5 分钟调度检查，实际完成时间受商品数量、队列和上游限流影响。
- 两次有效零库存确认、间隔至少 30 秒后才自动下架；补货后仅恢复已开启自动管理且因缺货下架的商品。隐藏商品恢复后保持隐藏。
- 对现有下架商品主动开启自动管理时，会先明确提示接管范围，等待后台重新确认有货后再恢复销售。
- 人工上下架或隐藏会暂停自动管理；锁定商品跳过自动调整。超时、限流、未知库存不会触发误下架，上游明确停售后需人工核实恢复。
- 按本地实际销售规格核查，规格修改或同步替换后丢弃旧库存判断。本地卡密、重复发货及混合来源不启用上游自动上下架；切换为本地或重复发货时自动暂停。
- 新增自动调整原因、检查时间及操作审计；人工操作或锁定前开始的旧检查不能覆盖最新状态。

## 批量处理

- “管理全部筛选结果”支持跨分页预览，单次最多 5000 件，分批执行；锁定、不支持及预览后发生变化的商品会跳过并显示原因。
- 网络中断保留已完成结果，可重新预览继续处理。结果汇总包含锁定跳过数量，电脑和手机均可操作。

## 升级说明

本版包含 SQLite / MySQL / PostgreSQL 数据库迁移，新增目录快照与商品自动管理字段，MySQL 分类名称列扩展至 100 字符。升级前备份数据库、配置和上传文件，低峰升级并检查迁移日志。后台与服务端须一起更新；Linux amd64 / arm64 完整包已内置后台和商城。

自动管理仅支持主站全部规格由上游发货的卡密商品。启用后独立于货源通用采集计划；要停止自动上下架，请在商品管理中暂停。所有自动管理商品均被锁定或货源停用时停止对应调度。

已完成后端全量测试、相关竞态检查、三种数据库迁移及 MySQL/PostgreSQL 并发验证、后台类型检查与构建，以及桌面和手机端交互回归。慢上游与浏览器测试使用本地模拟数据，真实上游仍需部署后验收；延长超时不能解决上游持续不可用、权限或出口网络问题。版本发布不代表客户站点已经升级。

发行包附 SHA256 校验和 ED25519 签名更新清单。Docker 用户可使用 `ZCARD_VERSION=v1.2.82 bash deploy/docker-install.sh` 更新。
