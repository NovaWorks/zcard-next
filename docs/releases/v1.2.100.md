# ZCard v1.2.100

发布日期：2026-10-01

## 接码渠道采集与旧商品转换修复

- 采集接码渠道商品时，归档同一供货连接下未锁定的旧接码明细商品，关闭这些明细的库存自动上下架，保留历史商品 ID、订单和接码会话。其他供货连接、普通商品及管理员锁定的商品不受转换影响。
- 修复接码渠道商品再次导入时，被普通商品的静态售价基线检查误判为人工修改而跳过的问题。渠道商品继续使用动态报价，不要求固定售价。
- 新导入检查点同时记录映射中的动态加价规则；任务排队后人工修改加价规则，会跳过冲突项，避免旧任务覆盖新设置。继续保留商品版本与锁定检查，兼容上一版尚未完成的导入检查点。
- 增加供货端目录 JSON 的签名 HTTP 契约回归，覆盖两次采集仅保留一个渠道商品、更新动态加价、不生成 SKU、不请求聚合库存及旧接码明细归档。

## 升级说明

本版无新增数据库迁移。从低于 v1.2.99 的版本升级仍需执行此前累积迁移；请先备份数据库、配置及上传文件，保留原加密密钥，使用完整发行包更新服务端与内置后台、商城，并刷新浏览器。

存量供货站点需先部署支持渠道目录的新供货端程序，并对原接码渠道重新执行一次导入或采集，生成并发布渠道商品；客户端再从对应 ZCard 供货连接重新采集。仅升级本客户端不会自动转换供货端目录。该版本不包含私有供货端程序的发布或部署。

旧明细商品归档后保留历史订单与会话；管理员锁定的商品保持原状态，需要管理员自行核对。接码新购继续默认开启，显式设置 `ZCARD_SMS_SALES_ENABLED=false` 可暂停新购，已有订单继续查单、操作和退款。

发布验证覆盖 Go 全量测试、受影响模块 `go vet`、接码渠道及导入任务的 race 回归、供货端目录 JSON 的签名 HTTP 采集契约，以及前后台生产构建和 fullstack 内嵌资源检查。

发行包内置后台与默认商城，提供 Linux amd64 / arm64、SHA256 校验和、ED25519 签名清单及 Docker 镜像，继续支持 Docker 后台在线更新。目录与协议测试不代表真实供应商付费取号、短信收取和资金闭环已验收；版本发布不代表客户站点已自动升级。
