# ZCard v1.2.118

发布日期：2026-11-20

## Telegram 订单提醒修复

- 补齐下单成功后的 `order.created` 事件。开启“新订单”通知后，可在创建订单时收到提醒；提醒明确注明下单不代表付款成功。
- Telegram 订单通知先持久化入队，再执行邮件、采购等处理，避免慢 SMTP 或上游请求拖延管理员提醒。
- Telegram 待发送任务的扫描间隔从 10 秒调整为 1 秒，保留原有投递租约、幂等、失败重试与限流处理。实际到达时间仍受任务积压、网络及 Telegram 接口状态影响。
- 人工发货商品付款确认后提示“待人工发货”，无需等待补发卡密。交付完成后单独发送“发货完成”，不再沿用待处理提示。
- 新订单、付款成功与发货完成继续分别遵守后台的通知事件选择。补发操作不重发付款事件。
- 下单报价、事务回滚不产生新订单提醒，重复提交同一订单不重复发布创建事件；分站订单不投递到主站接收位置。

## 升级说明

- 本版无新增数据库迁移。备份数据并保留原加密密钥，更新完整程序或 Docker 镜像并重启。
- 在“系统设置 → Telegram”确认通道和订单通知已启用，选择“付款成功”；需要下单及交付提醒时，另外勾选“新订单”和“发货完成”。原有 Token、接收位置、话题和事件开关继续生效。
- 发送定时任务运行于 `all` / `worker` 模式。拆分部署时请保持 worker 正常运行；网络失败或限流可在通知投递记录中查看。
- GitHub 提供 Linux amd64 / arm64 程序、SHA256 和签名清单。Docker 应用及更新器提供同样两种架构，版本标签为 `v1.2.118`，`latest` 同步更新。
- 本次发布不代发频道公告，也不代表客户生产站点已升级或完成真实订单验收。
