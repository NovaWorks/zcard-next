## 验证

- 两版实际本地服务、有 Redis / 无 Redis 共四组测试均通过。临时提交失败后恢复为 fulfilled，每组只有一次有效上游采购；请求执行期间并发调用重试，保持 pending，原请求随后正常交付。
- 两版实际 Redis 轮询都从 retry_count=1 推进到 2。直接检查 asynq:{critical}:scheduled，第一和第二次查询后均保存下一代采购轮询任务，任务标识不同，包含实际延迟。
- 故障队首商品之后的健康商品在三轮同步中都得到处理；渠道不再因该单品进入冷却，故障商品保留旧值并列入部分失败结果。HTTP 429、认证及网关拦截仍停止，连续多个相同频繁错误也保留渠道保护。
- 状态、价格及采集同步都能保存缺失的数字 page_id。已有有效编号、错误绑定及非法编号、原商品价格和状态保持保护；历史订单来源快照不改写。
- 新增 Go 回归覆盖到期扫描、原请求复用、重试抢占、取消订单、未知结果、并发提交等待及等待窗口到期、故障商品保留与同步任务上下文结束后的重试。
- 本版干净源码 server 全量 Go 测试通过：61 个测试包；go vet 通过。采购、货源与队列竞态测试通过；补充的最终并发保护再次通过两版采购竞态测试。
- 四个实际 Linux amd64 / arm64 发行程序都在隔离容器中运行并核对版本。两版容器均通过 SQLite 网页安装、前后台资源、容器内更新保护、重建后配置/密钥和上传文件保留检查。
- 正式发行全部附件已匿名下载并与本地逐字节比对，GitHub 附件大小及服务端 SHA256 一致；下载后的 update.json 再次通过 Ed25519 签名和产物 SHA256 验证。标准 latest/download/update.json 与本版签名清单一致。
- 以上服务测试使用独立临时数据库、模拟上游和本地 Redis，不代表客户订单 111 / 103 已现场恢复，也未调用真实采购或 Telegram Bot。
