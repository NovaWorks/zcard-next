# tghao 数量、报价、购买资料与预选卡

链路：tghao（`acg_faka`）→ zcard-market → ZCard Supply API → 开源 zcard-next。

## 升级和同步

同时升级两端服务端及店铺前端，执行各自版本化数据库迁移。先在 Market 完整同步或重新导入上游商品，再在开源版的 ZCard 连接重新同步商品。此前因不支持而下架的商品，需要核对后手动重新上架；同步不会覆盖运营人员的下架决定。

`minimum`、`maximum`、是否支持预选和是否必须实时报价会随商品同步。`maximum=0` 表示上游没有设定上限，两端不会再把它改成 99；仍受请求整数范围、实时可用库存和订单金额上限约束。已有本地商品保持原来的购买规则。

## 报价和下单

新客户端声明 `card_purchase.v2`，同时保留 `card_purchase.v1`。旧客户端看不到依赖新版数量、报价、表单或预选能力的商品，避免用目录单价直接扣款。

目录单价是展示参考。购买时按实际数量、规格、购买资料和所选卡片询价；ACG `valuation.price` 按整单金额处理。换汇和百分比加价按完整金额计算，固定加价仍按件数累计，最后进行金额取整。显式固定售价保留其定价语义，选择卡片时另计确认过的附加价。

开源版购买页及购物车复用 `POST /api/v1/storefront/orders/quote`，确认金额后携带 `quote_key` 建单。修改数量、规格、表单、选卡、积分选择、定价或商品配置后须重新报价。报价不会扣余额或创建采购；建单后冻结采购资料、成本、原币金额和汇率，订单有效期不超过供货报价有效期。报价返回 `expires_at`；积分确认使用服务端返回的 `points_total` 显示准确扣分。

供货侧新增两个经过原有 HMAC 鉴权的接口：

- `POST /api/supply/products/{id}/card/quotes`：提交 `sku_id`、`quantity`、`manual_form_data` 和可选的 `card_selection`，返回报价 ID、总额、附加价、数量、币种和到期时间。
- `POST /api/supply/products/{id}/card/drafts`：提交 `sku_id`、`page`、`limit`，分页返回预览和不透明选择令牌。

供货建单使用原接口，附带 `card_quote_id`、`required_capability=card_purchase.v2`、报价币种和准确的 `max_supply_amount_cents`。报价与账户、商品、规格、数量、表单及定价版本绑定，最多消费一次；相同下游请求号重放原回执。

## 表单与选卡

支持可表达的文本、密码、多行、数字及选项控件，保留正则、必填、选项显示名称和实际值。密码和多行资料不自动删掉首尾空格或换行。字段通过本地版本化别名转供，验证后的采购资料加密保存；上游凭据、原始选卡 ID 和真实卡密不会出现在公开商品目录中。

预选是可选能力：不选时随机交付，选定卡片时每次只能购买一份。上游起购数量大于一的商品不能通过单卡预选绕过限制。选卡不占用或锁定上游库存，最终报价及采购前会再次确认状态和价格。

无法准确表达的控件、正则或规格会明确拒绝，不静默丢字段。手动发货和其他原有不可转供类型仍不通过自动采购链路开放。

## 异常和资金

ACG 没有原子锁价或自动退款接口。采购前重新检查价格与库存，确定未提交的拒绝按原失败策略处理；真正提交后发生超时、断线或不明确回执，保留核对状态，不重新采购或自动退款。

实收回执与冻结报价分别保存。若询价后上游在成交瞬间变价，已成交订单不会被当成“未扣款”退款，也不会再次采购；保留实收成本及差额用于核对。供货退款与买家退款各自按本层真实成交金额处理。自动退买家余额沿用原有范围：单商品、会员、人民币、无手续费的余额付款；多商品、积分、游客和外部支付等订单保留人工核对，不凭上游状态退现金。

## 验证

双站验收只模拟上游，Market 和开源版运行独立二进制、数据库和钱包：

```sh
python3 scripts/test_tghao_card_integration.py \
  --market-bin /path/to/market \
  --opensource-bin /path/to/opensource \
  --output-dir /tmp/tghao-card-acceptance
```

本地模拟验收不代表真实上游扣款、真实卡密交付或生产部署验收。上游协议参考：https://tghao.uk/user/index/api。
