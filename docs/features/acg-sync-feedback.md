# ACG 商品同步兼容与失败处理

## 同步行为

- `config` 支持 INI 字符串、空 PHP 数组 `[]`、空对象和已解析的标准配置对象。重复键、损坏规格和未知结构会报错，不将其当作无规格商品。
- 单件商品报价失败时保留原商品、价格及 SKU，继续处理其余商品；任务汇总成功、失败和跳过数量。部分成功显示“部分完成”，真实失败仍保留失败状态；报价失败的任务不执行未见商品下架对账，也不推进同步锚点。
- 只读接口明确返回停售、不存在或不支持自动采购时，跳过报价；报价同步不修改上下架状态。采集和状态同步跳过已确认不可采购商品的库存补查，明确停售不作为未知库存错误。
- 报价、目录规格补查和库存补查遇到限流或认证失败时，停止后续读取；当前库存批次已发出的并发请求会正常收尾。库存补查阶段中止时，本页商品尚未写入，此前完成的商品保留。
- 普通同步重试重新统计本次进度并清理旧错误；可恢复导入继续保留已保存的商品进度。库存失败可单独重试失败库存。

## 请求间隔

渠道“定时计划”中的三个参数各自生效：

| 参数 | 单位 | 默认值 | 范围与作用 |
| --- | --- | --- | --- |
| `request_delay` | 秒 | 1 | 0–60，商品分页之间的等待 |
| `quote_request_delay_ms` | 毫秒 | 500 | 100–10000，同一任务的规格读取及每次报价 HTTP 请求，包括逐 SKU 请求和重试 |
| `stock_request_delay_ms` | 毫秒 | 200 | 0–10000，库存补查批次之间的等待；批内并发仍由 `stock_concurrency` 控制 |

设置 500ms 报价间隔应填写第二项，不应在秒字段中填写 500。正常采购使用原有请求策略。

货源任务的执行预算统一为 6 小时，Redis 队列与进程内执行使用相同预算。目录尚未返回时也每 15 秒更新任务心跳并检查取消，避免慢速读取被看门狗误判；达到上限或被取消时会记录终态，已完成商品保留。

## 数据语义

目录库存仍只作为参考，实际库存需要独立确认；不根据 `shared_sync` 推测可售库存。仅有 race 的 `美国|` 是合法 SKU 编码，不因末尾分隔符删除。`category_map` 是本地分类映射，移除映射不等于排除同步商品。

验证使用本地 HTTP 响应和 SQLite 数据库，覆盖配置格式、逐规格报价/库存汇总、单品失败隔离、限流与认证中止、重试进度以及后台桌面/手机交互。客户反馈未包含原始接口响应及完整运行日志，不能据此确认客户现场的商品数量或历史数据库操作。
