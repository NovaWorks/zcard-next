# 19csn 服务渠道

驱动名为 `csn19`，通过官方 `POST /api/v2` 表单接口采购异步服务，复用现有服务商品、会员余额付款和订单进度流程。本地接入已完成，2026-11-21 已使用真实账号完成只读联调；尚未实际采购或发布新版本。

## 配置与购买

1. 后台「渠道 → 货源渠道」新增「19csn（服务渠道）」。
2. 上游地址填 `https://19csn.com`、`https://19csn.com/api` 或完整 `https://19csn.com/api/v2`；接口地址会统一到 `/api/v2`。只需填写账号 API Key。
3. 测试连接读取账号余额及真实币种。人民币账号汇率填 1；其他币种按账号币种对人民币的汇率配置。公开文档中的 USD 响应只是示例，不用于替代真实账号币种。
4. 预览、导入服务目录，选择跟随渠道或商品定价规则。服务不使用普通卡密单价，客户登录后填写链接、数量或评论，确认本次总价，再使用余额付款。

当前开放 `Default` 单次服务和 `Custom Comments`。自定义评论保留原文、顺序和重复内容，每行一条，不允许空行；数量由行数计算，不向上游编造 `quantity`。普通服务遵守接口返回的最小和最大数量。

公共服务页标注「每千人价格」，普通和自定义评论费率按 1000 单位计算。供应商小数费率完整保留到整单换汇，成本向上取到人民币分，再按本站规则加价；不会先把每份成本取到分后再乘数量。前台不公开上游费率、币种成本和凭据。

`Package`、`Subscriptions` 和多次循环投放暂不开放采购：公开文档不足以确认套餐总价、订阅预算和循环扣款规则。它们不会按普通服务数量强行下单，需取得真实账号样例及明确计费依据后扩展。

## 订单及操作

- 支持 `services`、`balance`、`add`、`status`、`cancel`、`refill`、`refill_status`。客户能否取消、补量仍取决于当前服务返回的能力及订单状态。
- 每个采购任务在发送 `add` 前持久化提交标记。上游没有公开幂等键：超时、断连、无效回执、订单 ID 丢失或提交后进程中断，统一转待人工核对，不自动重复采购或自动退款。
- 付款前后保存原报价、用户、服务、参数及连接身份；实际提交前重新读取服务规则，规则或汇率配置变化时在调用上游前拒绝。上游没有报价锁定/最高扣款参数，不能保证检查与扣款之间上游费率绝不变化；后续异常金额须核对。
- 订单状态保留开始数量、剩余数量及服务进度。`Partial`、取消、失败和无法识别的状态标记结算待核对，不根据剩余数量计算或推断到账退款。
- 取消确认仅代表申请受理，需继续查订单；补量保存供应商补量 ID 再查进度。两类操作均先落提交标记，结果不明时不重复发出。
- 凭据不进入 URL、错误信息或日志；包含凭据的表单不跟随 307/308 重定向。购买参数加密存储。
