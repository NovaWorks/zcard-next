# 商城首屏配置与加载恢复

## 修复原因

Classic 通用构建没有客户站点的数据库，原先会把构建时请求失败的结果（`fetch failed`、空分类、默认横幅和页脚）写入 HTML。浏览器执行脚本后才读取真实设置、替换外观；脚本失败时则停留在错误页面。页脚还会等待购物车读取，扩大了默认内容出现的时间。

## 当前实现

- 通用构建输出中性的加载页面和可直接使用的刷新链接，不再预渲染虚假的客户业务状态；Go 原有的爬虫动态 SEO 渲染继续保留。
- 请求 HTML 时，服务端通过公开配置白名单生成站点当前配置，并注入主题颜色和尺寸 CSS。CSS 仅接受受限数值和十六进制颜色，JSON 保持 HTML 转义；密钥和后台入口不进入公开快照。
- 配置以单次数据库列表查询读取。数据库故障返回错误，不能冒充“配置已恢复默认”。主题发布值及预览值沿用原来的请求上下文合并流程。
- 客户端各模块共享配置快照和并发请求。购物车、验证码、交易等业务设置仍强制读取最新配置，视觉快照不会被这些请求阻塞。有效快照短暂复用 30 秒；刷新页面直接使用新 HTML 的配置，不使用 localStorage 持久化业务配置。读取失败保留本页最后成功的外观，不覆盖为默认。
- 主题发布的新值可以覆盖旧首屏值；只有预览保持草稿覆盖。清空配置会移除旧 CSS 覆盖和旧页脚内容。站点外观不再等待购物车或登录请求。
- 首页、列表页立即渲染加载状态，分类和商品分别显示失败、空结果及重试。可选横幅不会阻塞商品列表；桌面和移动端均有恢复入口。
- 配置与目录只读请求每次最多等待 8 秒，对网络错误、408、5xx 最多额外重试一次。永久性 HTTP 错误不自动重试。下单等写入不继承此重试机制，商品列表保留会员 Authorization 以维护会员价格。
- 页面可见并在闲置后返回时刷新目录；断网恢复触发重试。合并 focus/visibility/online 事件，避免重复请求，并保留浏览筛选状态。
- 未改变的配置不会重复通知消费者，重新读取配置也不会重新弹出已关闭的维护提示。

## 验证

自动回归：

```sh
pnpm --dir storefront type-check
pnpm --dir storefront build
node scripts/test_storefront_bootstrap.mjs
cd server
go test -race ./internal/platform/theme ./internal/mods/settings
go test -tags fullstack ./internal/web ./internal/mods/settings
```

模块测试覆盖：首屏种子、并发合并、新配置发布、恢复默认、主动清空、非法响应、请求失败后保留、预览优先级、新文档隔离、请求超时及重试上限、会员身份、写入不重试、构建 HTML 无错误残留、敏感配置不泄露、CSS/JSON 注入防护。

本地生产构建浏览器检查：正常加载、商品与分类同时 503、分别点击重试恢复、更新配色/页脚及清空导航、390px 手机布局、脚本 503 时仍显示正确颜色和刷新入口。

此文档记录实现和本地验证；不代表已提交、发布或升级客户站点。客户曾经长时间卡住的具体网络/脚本失败触发条件仍需客户服务器请求日志确认。
