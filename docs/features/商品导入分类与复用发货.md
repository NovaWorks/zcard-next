# 商品导入、关键词分类与复用发货

版本：v1.2.81。功能、验证和升级说明见 [发行说明](../releases/v1.2.81.md)。发行包发布不代表客户站点已安装更新。

## 操作入口

- 货源 → 导入商品：全选全部商品、全选搜索结果、仅选未导入、清空选择。搜索不会丢失其他分类的已选商品，锁定商品不可选。
- 导入窗口 → 自动分类：关键词、排除词、任意/全部匹配，按规则顺序优先匹配。支持保存本货源规则，以及对单件商品手动覆盖。分类预览每页 50 件。
- 商品管理 → 按关键词分类：扫描本站全部非删除商品（包含下架商品），预览后应用。保留已手动分类的商品，跳过锁定商品；预览后被修改的商品显示冲突并跳过。一次最多修改 1000 件，超过时要求缩小关键词范围。
- 商品管理 → 发货设置：按规格选择每单上游采购、自己的单次卡密、重复发货。

## 分类优先级

本次单件手工指定 > 已保存的手动分类 > 首个命中关键词规则 > 上游分类映射。关键词使用 Unicode NFKC 归一化及不区分大小写的包含匹配，不执行正则表达式。

分类保护从本次功能开始记录；升级前的手工分类无法可靠还原，首次处理既有商品应以预览结果为准。

批量指定分类默认只修改本次选中商品。只有明确选择保存整个上游分类映射，才改变分类映射默认值。单件分类写入 `category_protected`，后续上游同步保留该分类；人工批量改分类仍可更改它。

## 发货来源

| 来源 | 内容与库存 | 上游采购 |
| --- | --- | --- |
| 每单上游采购 | 沿用原流程 | 每单采购 |
| 我的卡密 | 本商品、本规格的本地卡密，一条只卖一次 | 缺货也不会回退到上游 |
| 重复发货 | 一个内容版本，多笔订单共享；可设有效期和最多发放次数 | 仅明确选择首次自动采购时购买一次 |

重复发货支持三种内容来源：手动填写、选择本商品同规格成功且未退款的历史采购内容、首次已付款订单触发单次采购。历史采购有多份内容时必须选择其中一份。

每个规格独立设置。启用本地发货的商品由商家维护价格、规格和上下架，上游采集、核价、库存补查及删除对账会跳过它。混合规格商品的其他上游规格，下单时仍进行实时库存校验。

商品页及购物车将重复发货规格限制为一份；服务端再次检查，不能通过直接调用接口绕过。商品锁定后不可更改发货设置，但正常下单、采购结果核查与交付仍可进行。

## 采购和恢复

共享内容保存在独立的 `product_delivery_sources`，订单项保存 `delivery_source_id`。它不依附于首位买家的订单，也不复制成多条一次性卡密。

状态：等待首次采购 → 采购中 → 原单查询 → 可重复发放。先到的成功回调不会被迟到的采购响应改成失败或不确定状态。采购请求号使用持久化 UUID，避免不同商城共用上游账号时发生编号碰撞；数据库比较并更新状态确保多进程只有一个采购发起者。进程退出、网络超时等未确认结果进入待核实状态，禁止再次提交采购。

- 待核实时，运营人员核对原上游订单号，再使用“核查原采购结果”；只查询原单。
- 货源账号配置与首次采购不一致时拒绝核查，需恢复原账号配置。不会自动用另一账号购买替代内容。
- 内容失效、到期、暂停、上游拒绝或不确定时，相关订单等待商家处理，不自动退混合订单的整单，也不自动重新购买。
- 所有买家退款后，已发出的采购仍会由后台查询保存结果；不会因原买家退款使其他订单失去内容。
- 无 Redis 时，5 秒周期的数据库恢复任务仍可继续查询和交付。

新内容创建新版本，历史订单仍读取原版本。发放次数同时检查订单预占和实际交付，已交付后退款不归还次数；超时订单后来付款也不能突破实际发放上限。

## 安全与兼容边界

内容加密落库，管理设置接口不返回内容明文，操作审计对自填内容脱敏。历史内容取货继续走已有订单访问验证。

包含客户专属填写字段的商品不允许配置重复发货；已配置重复发货后也不能新增此类字段。普通商品/规格编辑接口不能绕过发货设置切换来源。

旧的同步供货购买接口不能表达这些混合发货模式，因此配置本地/重复发货的商品从这些接口排除，并在扣款前拒绝购买。商城购买流程正常支持。

首次共享采购按来源配置时的汇率计入一次采购成本；后续复用订单不重复计采购成本。历史采购内容不重复入成本，内容换版或原买家退款不抹掉已发生的采购支出。采购成本未确认时延续报表的“成本未完整记录”口径。自填内容没有系统内采购凭据时也按成本未记录处理，不假定为免费取得。

测试覆盖：规则归一化/排除/优先级、单件分类与整类映射隔离、预览冲突、锁定和租户检查、来源换版与历史内容、同商品规格隔离、并发首购、网络结果不明确、退款隔离、暂停/过期/次数上限、采购成本、审计脱敏、数据库迁移，以及桌面/手机端操作流程。

上游网络行为采用本地测试网关模拟；没有向真实货源下单扣款。发布前仍需按正常发布流程构建部署并在测试货源完成真实采购验收。

## 目录超时与分类名称修复（v1.2.82）

本节记录 v1.2.82 的修复；发行版更新不代表客户站点已部署。

### 目录加载

此前目录请求同时受管理接口和上游 HTTP 客户端的 30 秒限制；页面等待结束会取消上游请求。原目录缓存只有 60 秒，选择商品期间缓存过期，提交还可能再次下载整个目录。

新版管理后台采用持久化后台任务：创建任务后立即返回，页面每 2 秒读取状态。单次只读上游请求放宽到 120 秒，临时网络故障最多重试一次，整个目录任务最多运行 5 分钟。认证或权限拒绝不会自动重试。采购下单继续使用原有超时和重试策略。

- 加载期间可关闭窗口，后台继续；重新打开同一货源会复用正在进行的任务。
- 完整目录保存为数据库快照，有效期 2 小时。15 分钟内再次打开优先复用已完成目录；刷新创建新版本，其他窗口使用的未过期版本仍有效。
- 提交导入和展开商品核价携带快照编号，避免选择时间过长后重新下载目录。正式导入仍逐件核价，快照不保证当前价格或库存。
- 快照按站点、货源和账号配置隔离；账号变化或目录过期时要求重新加载。页面保留当前选择、分类草稿和定价设置，移除新目录中已不可用或锁定的选择，并显示数量。
- 失败任务显示可操作的中文提示，不会循环创建任务或反复弹出底层错误。点击“重新加载”才再次尝试。
- 无 Redis 时同样可用。每 5 秒扫描待执行任务；进程中断后，旧工作租约到期（330 秒）可恢复。连续中断超过三次后转为失败，等待人工重试。
- 每进程最多同时加载四个目录，数据库租约防止多个进程重复处理同一任务。目录最多 100 页、50000 件商品，响应及存储快照有 32 MiB 限制，超限不保存残缺目录。

### 分类名称

原 Ent 校验限制为 60 **字节**，与页面及接口允许 100 字符不一致，导致部分中文分类提交时出现 `Category.name` 校验错误。现统一为去除首尾空白后的 1–100 个 Unicode 字符，中文及单码点表情均按一个字符计算。

导入页面显示字符计数；提交前汇总所有异常名称，并支持点击定位。服务端在写入分类前再次统一校验，避免部分分类创建后才报错。普通分类新增和修改使用相同规则，不自动截断名称。

### 升级与验证

需要同时更新管理后台、后端及数据库迁移：新增 `supply_catalog_snapshots` 表；MySQL 分类名称字段扩展到 100 字符，PostgreSQL / SQLite 原字段无需扩容。三种数据库迁移均由 Atlas 生成。旧客户端保留同步预览接口行为，必须更新管理后台才能使用后台加载流程。

本地验证包括：故意延迟 31 秒的实际 HTTP 测试上游（页面请求结束后仍成功完成、仅请求一次上游）、并发任务去重、进程恢复、旧租约写入隔离、跨站点和账号检查、快照刷新与过期、中文及表情名称边界、三种数据库迁移，以及桌面和 390px 手机端错误定位、保留选择后重新提交。后端全量测试、管理后台类型检查和生产构建通过。

上述慢上游测试使用本地模拟接口；尚未在客户服务器部署新构建，也未验证新构建访问真实出海上游的结果。若上游持续不可用，延长超时和后台任务会提供明确失败状态，仍需排查服务器出口、上游权限或网关限制。

## 库存组合筛选与自动上下架（v1.2.82）

商品列表拆成“上架状态”和“库存状态”两组筛选，可与货源、分类、锁定状态及自动管理状态组合。例如“已下架 + 有库存”用于人工检查恢复销售，“已上架 + 无库存”用于检查缺货展示。新库存筛选在服务端分页前计算，使用实际发货来源的缓存，不在打开列表时请求上游。库存告急指大于零且低于预警阈值，无库存指确认零库存，过期或失败归入待确认；旧 API 的低库存参数保持兼容。

“补货待上架”只显示系统观察到从缺货变为有货、当前仍下架且库存未过期的商品；已有商品无法还原历史缺货过程时，可先使用“已下架 + 有库存”。手工改变销售状态会清除待上架标记。

### 操作方式

- 商品行点击“自动上下架”，或选中商品后打开“自动上下架设置”。
- “管理全部筛选结果”包含其他页，预览最多 5000 件，超出要求缩小范围；每次提交分批处理 100 件。预览固定目标和版本，提交跳过锁定、状态变化及不支持的商品，显示逐件结果。网络中断后重新预览，已完成部分保留。
- 单件或批量支持开启自动管理、暂停自动管理、人工上架、人工下架及人工隐藏。人工状态操作会暂停自动管理，包括对已下架商品再次执行下架。
- 开启自动管理会明确接管所选下架商品：不会立即读取旧缓存上架，后台重新确认有货后才恢复。原来因缺货自动下架的隐藏商品恢复隐藏；其他主动接管的下架商品按公开上架处理。
- 选择货源后可点击“检查该货源库存与补货”。任务在后台运行，离开页面不取消；失败可到货源任务列表查看。本操作只对已启用自动管理的商品修改上下架，其他商品仅记录库存观察。

### 自动规则及保护

自动管理默认关闭，仅支持主站全部规格由上游发货的卡密商品；自营、人工发货、本地卡密、重复发货及混合来源暂不支持。改为本地或重复发货时自动暂停。

开启后通过现有同步队列和数据库租约运行独立的 `listing` 检查，约每 5 分钟调度一次完整目录，实际完成时间受目录规模、队列和限流影响。无需开启货源通用采集/改价计划，也不启用这些计划。停用货源后停止检查；全部自动管理商品都被锁定时不派发此类自动检查。

- 两次独立有效零库存观察至少间隔 30 秒才因缺货自动下架；中途出现库存未知会重新开始复核。上游明确停售则停止销售，后续需人工核实恢复。
- 只有已启用自动管理、下架原因为缺货、上游可售且本地售价有效时才自动恢复。隐藏商品保留原展示状态。
- 按本地实际销售的上游规格检查库存；任一规格确认有货即可售，全部确认无货才视为缺货，未知规格不当成零。不使用其他上游规格的库存替代本地规格；检查期间人工修改或采集同步替换规格时，库存缓存和自动上下架均丢弃旧判断。
- 超时、限流、库存过期或未知不改变销售状态，不会批量误下架。限流停止当前检查，沿用货源冷却和失败任务机制。
- 写入前再次获取商品保护锁；人工操作、锁定/解锁之前开始的旧观察不能覆盖新状态。暂停自动管理只保留当前状态，不替用户上架。
- 自动上下架写入操作审计；商品列表展示自动管理状态、最近检查时间和处理原因。锁定保护商品维护，正常订单交付规则保持原样。
- 新导入任务的后续库存补查也识别人工上下架/自动管理设置变化，不会凭旧导入记录重新上架。

### 数据升级与验证

增加商品自动管理开关、下架原因、恢复状态和库存观察字段；三种数据库迁移均由 Atlas 生成，SQLite 只新增列，不重建商品表。历史商品默认不启用自动管理，保留原上下架及锁定状态。

本地测试覆盖组合筛选、真实缺货后补货、库存未知、两次确认、隐藏恢复、人工暂停、锁定与解锁旧观察隔离、跨站点、混合发货来源、预览冲突与重复提交、规格集合变更，以及 MySQL / PostgreSQL 迁移后的并发恢复。浏览器使用本地模拟数据验证桌面及 390px 手机端组合筛选、批量预览、锁定跳过和操作结果。本节不代表客户站点已经更新。
