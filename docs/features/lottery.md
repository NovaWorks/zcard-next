# 会员抽奖

从后台「营销管理 → 抽奖活动」创建活动。没有发布中的活动时，商城导航不显示抽奖入口；已有记录始终可从「我的奖品」查询。Classic 内置；云帆需安装 0.1.3 或以上适配包，其他主题可接入 `/api/v1/storefront/lottery/*`。

## 配置与发奖

1. 填写活动名称、时间、时区和说明。添加 1～12 种奖品，概率精确到 0.01%，合计大于 0 且不超过 100%；剩余概率为「谢谢参与」。每次独立抽奖，可以重复中奖。
2. 发放方式选择「系统发卡」「自动文字/链接」或「平台人工领取」。文字/链接会把相同内容发给每位中奖者；不同卡密请选系统发卡。人工领取只需填写说明，实际交付后在中奖记录中确认已发放。
3. 系统发卡必须选择在售普通自营卡密商品；有规格的商品必须指定规格。不支持上游代发、隐藏分类、必填购买控件、靓号和发后即删商品。中奖会消耗一张可售卡密；普通商品库存和奖品额度都必须充足。
4. 设置登录参与赠送次数：活动期间一次、每日一次，或关闭自动赠送。每日次数按活动时区清零，不累计；重复登录、换设备、暂停再恢复都不会重复赠送。可给指定账号补发次数并填写原因，每日活动补发的次数也只在当日有效。
5. 保存为草稿，用预览检查展示，再发布。预览的模拟抽奖不会写中奖记录或扣库存。发布后修改奖品需先暂停；次数规则、时区与开始时间固定，需要改变时复制成新活动。

任一有中奖概率的奖品额度耗尽、库存不足或商品变得不可发放，抽奖会暂停，详情显示暂不可用。补充后自动恢复；不会偷偷重抽、提高其他奖品概率或改成未中奖。活动剩余份数表示活动额度，不是商品实际可售库存。概率为 0 的奖品不影响可用性。

## 用户与运营

游客可看活动，登录会员才可参与。抽奖成功后显示结果，卡密或领取说明保存在「我的奖品」，刷新页面也可查询。网络中断时点「重试上次抽奖」继续确认同一笔结果，不会再次扣次数。

后台中奖记录可按活动、用户名/完整中奖编号、状态和时间查询，默认只显示中奖，勾选「包括未中奖」后显示全部。人工确认只表示已经实际交付，不会创建商品订单或再次发卡。已确认记录重复提交不会覆盖首次发放信息。库存中对应卡密显示「已发奖」。

新安装的运营/客服角色包含查看记录和人工确认权限。已有角色权限不会自动覆盖，需要管理员分配 `lottery:read`、`lottery:deliver`。配置、发布与补次数分别要求 `lottery:write`、`lottery:grant`；查看私密内容要求 `lottery:reveal`。这些敏感权限受现有管理权限规则控制。

## 数据与兼容性

新增六张 `lottery_*` 表，支持 SQLite、MySQL、PostgreSQL；没有修改原订单、支付、钱包、返佣或退款数据结构。默认启动自动迁移，关闭自动迁移的安装先运行 `zcard migrate`。保留网站原有卡密加密密钥；更换密钥会导致原卡密及奖品内容无法解密。

抽奖结果、扣次数、额度计数和卡密发放在同一事务提交。请求标识唯一，账号与活动隔离，卡密 ID 唯一绑定中奖记录。已发奖卡密不能重新启用；活动引用的商品/规格与历史发奖记录受删除保护。中奖内容加密保存，普通请求日志、规则历史与操作快照不保存明文；查看奖品内容另有审计。

升级前按现有部署流程备份数据库和加密配置。回滚旧程序前先结束所有抽奖活动，保留新增表和加密密钥；旧主题不受路由影响，但不会自动获得抽奖界面。免费账号次数不等于实名次数控制，本版没有邀请奖励、付费抽奖或设备风控。
