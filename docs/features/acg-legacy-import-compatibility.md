# ACG 旧版货源导入兼容修复

日期：2026-09-26。本文记录本地修复与只读联调，不代表客户商城已升级。

## 问题与证据

出海货源认证成功，目录曾实测约 41 秒返回 5,491 件商品；这说明长目录仍需要已有的后台加载和有限超时。本次商品导入停滞是另一个问题：`/shared/commodity/valuation` 返回 HTTP 200，但响应是包含 Base64 404 页的脚本。旧代码把它归为 429，触发商品重试和渠道冷却。

`/stock` 同样缺失；`/item` 返回分类数组及 children 商品，并非单个库存对象。`/inventory` 则能返回普通商品及 race 规格的库存与旧版账号报价。

## 修改

- 仅在只读报价请求收到明确的接口缺失响应时启用旧版兼容。401、403、真正的 429、5xx、未知 HTML、业务拒绝和无效报价不能触发价格替代。
- 旧版普通商品读取已签名 inventory 响应的 `factory_price`；race 商品读取完整 `category_factory`，不使用目录价、`user_price` 或 category 展示价替代。校验发货方式、预选状态、规格标记、价格精度、重复/缺失规格和配置完整性。
- `[sku]` 组合附加规格无法由旧版接口可靠确认，保持失败，不按基础规格价格猜测。库存也不能把组合规格请求降级成总库存请求。
- 一个商品不能混合现代 valuation 和旧版价格；报价规格缺失时不能删除已有目录快照中的 SKU。旧版能力只缓存在当前渠道适配器实例，不跨账号或站点共享。
- 旧版 item 分类树必须精确匹配唯一商品。只有匹配成功且缺少库存字段时继续使用 inventory；错误商品、重复商品、损坏库存不触发兜底。
- inventory 无 race 参数时可能只返回默认规格库存。商品总库存逐 race 查询汇总；任一查询失败、数量无效或溢出，整个结果保持未知，不写入部分库存或错误零库存。
- 原有导入检查点、锁定/人工编辑保护、失败重试和库存单独重试流程保持使用；不会自动重建任务或覆盖已成功商品。

## 验证

新增 `acg_legacy_test.go` 复现并覆盖 HTTP 200 + Base64 404、HTTP 404、现代报价错误不可降级、缺价/损坏配置、SKU 丢失、混用协议、库存树匹配、规格总库存、部分失败、无限库存、溢出及缓存接口与规格请求兼容。

渠道模块回归和适配器竞态测试已通过。新增可选只读联调 `TestAcgLiveQuoteAndStockSamples`，从环境变量读取凭据与少量商品编码，默认跳过，不请求 trade。

## 已存在任务的恢复

升级到包含此修复的服务端后，已完成的商品保留。对停止或结束的任务使用“继续未完成”或“仅重试失败”；已保存商品的库存问题可单独重试库存，无需重新导入全部商品。

历史误判产生的渠道冷却仍可能保留到原截止时间（原机制最长一小时）。修复不直接清除这类状态，因为旧记录不能可靠区分真实限流和误判；等待冷却结束后恢复。运行中的任务需先正常停止再继续，避免并发导入。

本次没有修改线上商品、渠道设置、执行采购或发布新版本。
