# 可恢复的商品导入

商品导入现在立即返回后台任务，前端通过原货源「任务」入口查看进度。分类映射、所选商品快照和导入参数随任务一起提交，不再依赖页面保持打开或预览缓存存活。

## 执行与恢复

- `ImportProducts` 返回 `task`，不再返回整批同步执行的最终计数。前后端需一同升级。
- 同一次提交的网络重试复用 `request_key`；相同键配不同参数会被拒绝。
- 每件商品独立报价、保存和查询库存，取消了整批共享 20 秒报价及 8 秒库存额度。
- 商品、规格、映射与“已保存”检查点在同一事务提交；库存失败只重试库存。已保存商品会释放大体积预览快照。
- 数据库保存任务和商品明细，Redis 非必需。每 5 秒扫描待执行任务；异常退出后，旧连接执行租约最长约 120 秒过期，再由新执行器接续。
- 一个货源同一时间只执行一个维护任务；旧执行器在失去租约后不能提交导入结果。采购下单不加入维护任务队列。
- 超时、网络和上游临时故障每阶段最多尝试 3 次，使用递增等待和少量错峰；限流尊重 Retry-After，并暂停该货源的继续请求。认证或访问拒绝暂停任务供人工处理。
- 停止任务保留成功结果。库存单独重试不会恢复同一任务中已停止的其他商品。

## 商品保护与展示

- 保存前重新检查商品锁定、可编辑内容和人工价格/规格价格；冲突商品明确显示跳过。
- 货源账号、汇率、渠道定价、分类映射或启停状态变化时暂停。继续前必须检查并明确确认当前配置；已保存商品仍只处理库存。
- 新商品在库存确认前不上架。补查完成前再次检查商品内容，避免恢复上架时覆盖人工操作；待定价和不可售商品保持下架。
- “库存待确认/库存失败”属于已保存商品的子集，不计作新的导入失败。只有处理结束才显示完成，未处理商品不被批量标记为失败。
- 手机使用商品卡片展示问题，桌面使用明细表格。轮询断网时显示持久的重新连接提示，不反复弹出错误消息，也不重新提交导入。
- 有待执行或正在处理的任务时，禁止删除货源。

## 数据库与验证

Ent schema 增加 `supply_import_items`，并为 `supply_connections`、`supply_sync_tasks` 增加执行租约、提交去重和导入参数。三种数据库均提供 Atlas 生成迁移；SQLite 升级测试检查旧凭据、映射、价格基线和历史任务保留。

回归覆盖 1168 件商品独立报价、SQLite 关闭后重开续接、无 Redis 扫描恢复、商品与检查点回滚、锁定/人工改价/配置变更、重复提交、库存重试范围及 MySQL/PostgreSQL 租约。浏览器测试：`scripts/test_import_tasks.cjs`，使用本地 API 固定数据，不访问客户后台。
