# 实体商品流程完善计划

日期：2026-10-03。用户已授权复查后实施，并在开发验收后要求提交、推送、更新频道发布文档及发布正式版本 v1.2.108。

## 确认需求

1. 新增独立 `product_property` 商品属性字段（virtual/physical），后台按此判断商品属性。`goods_type` 作为兼容镜像，迁移回填并在存储边界保持一致；商品分类不能改变属性，已有商品属性不可切换。
2. 商品后台分别控制是否管理库存、是否显示库存、是否显示已售。显示开关复用 `stock_visible` 并新增 `sales_visible`；最终展示同时受主题全站开关影响。
3. 实体商品支持关闭库存管理：商品/SKU不扣库存、库存输入及买家数量隐藏、持续接单；上架状态、配送范围和限购照常生效。规格继承商品开关。
4. 订单项保存 `inventory_tracked` 快照。旧实体订单按原规则预占及归还；不管理库存的新单取消/退款不补库存。重新开启必须核对可售库存；退货登记独立幂等，不能依赖库存变动作为唯一记录。
5. 纯实体下单不再要求查询密码。会员使用订单所属账户；游客使用自动生成的订单专用安全访问凭证，支付回跳、查物流与确认收货共享授权。游客邮箱用于独立用途验证码恢复访问，余额支付始终只允许账户所有人。
6. 实体商品隐藏虚拟专用配置、取货、卡密交付与上游采购界面及文案，提交与服务端也限制残留虚拟参数。混合订单分别呈现并保持完整授权，查询虚拟交付不能提前完成未收货实体项。
7. 地址按 Country → Address line 1 → Address line 2（选填）→ Suburb or city → State/Province → Postal code 展示，姓名、电话及邮箱为联系区。国家决定地区/邮编要求，中英文与自动填充一致；第二行独立字段，兼容旧地址/旧幂等请求，不把 district 改为公寓字段。

## 实施分工与复查结论

- 模型、API、三数据库增量迁移与前后台集成：主代理。
- 目录属性、展示字段与旧客户端兼容：目录代理。
- 库存快照、取消/退款/退货：库存代理。
- 游客订单授权、邮箱恢复与混合订单完成状态：授权代理。
- 原 `docs/plans/` 未跟踪工作保留，不改动其他计划。

## 验收

- 实体属性显示正确；旧API省略新增开关不覆盖已保存设置；属性冲突及虚拟内容拒绝。
- 库存/已售在商品卡片、详情和相关买家页面一致；全站关闭优先；后台库存管理不受展示开关影响。
- 有限/不限库存、规格、模式切换前后旧订单、最后一件并发、取消/超时、未发货退款、退货重复提交均保持正确。
- 游客无密码下单、同幂等键重试、外部支付、查单、确认收货、邮箱恢复；跨订单、跨分站、错误凭证和验证码重放拒绝。
- 地址第二行创建/更正/包裹快照保留，旧订单可读，国家变化与字段错误明确。
- 混合订单查看卡密仍等待实体收货；历史虚拟及密码订单兼容。
- Go相关测试/竞态、迁移检查、前后台类型检查/生产构建和浏览器完整流程。

## 已实施与验收记录

- 新属性在数据库、管理 API、店面 API 和后台编辑器统一；已有 `goods_type` 回填到新字段，仍作为旧客户端镜像。后台类型列优先判断商品属性，分类仍仅负责归类。
- 三个商品开关互相独立：`track_inventory` 控制是否计数，`stock_visible` 控制买家数量展示，`sales_visible` 控制已售展示；关闭计数时买家库存数字始终隐藏。显示字段显式返回 `false`，省略更新不覆盖保存值；主题全站关闭具有最终优先级，配置读取前不会闪现数字。
- 游客实体订单使用 256 位随机订单凭证；查询通过请求头传递、分享链接通过 URL fragment 传递，避免进服务器 URL 日志。创建幂等重试使用安全随机请求键、加密初始凭证；找回后清除重放密文并轮换凭证。邮箱验证码有专用用途、有效期、冷却和尝试次数限制，一次消费；验证码/凭证不进通知或请求日志，订单接口禁止缓存。
- 库存停用保留原数量；订单项快照决定取消、超时、退款和退货的库存动作。独立退货回执支撑不限库存退货登记和重复请求。重新开启商品级库存需明确核对数量，规格继承开关，库存开关变化使旧报价失效。
- 地址第二行独立保存及展示；空第二行从规范化输入中省略，旧请求指纹保持兼容。国家元数据决定 city/state/postal 等字段及必填要求，地区/国家支持中英名称，输入错误与字段逐一对应。姓名/电话在联系区，游客邮箱在购买信息区。
- 已完成 SQLite、MySQL、PostgreSQL 的增量迁移和历史数据保留测试；真实 MySQL/PG 覆盖实体库存抢占、发货/退款竞争、资金/优惠券并发，以及新库存开关和退货幂等。保留旧订单和虚拟交付数据。
- 前后台类型检查、英语字典检查、地址 TS/Go 回归、Go 全量测试、授权专项竞态、Go vet 和前后台生产构建均已执行。最终嵌入前端构建使用 `make build-fullstack`，迁移/接口均随二进制构建。
- `scripts/test_physical_commerce.cjs` 在独立本地 SQLite 实例验证真实 HTTP 与生产店面：后台三个开关、纯实体无密码下单、两行地址、支付授权、签名回调、发货、确认收货、查单不取卡、新设备邮箱找回、凭证轮换、访问链接清理。付款网关和 SMTP 仅为本地 fixture，未连接真实支付或外部邮箱。
- 实际表单组件在 320/390/1280px 下完成布局、逐字段校验、国家切换和第二行交互检查；没有横向溢出。

## 部署和主题边界

仓内后台与内置店面开发及本地验收已经完成，正在准备 v1.2.108 正式发行。已安装的独立主题不会自动获取内置店面 Vue 修改；如使用独立 Gift，需要按新增字段、订单凭证和两行地址契约适配并重新打包主题。线上邮箱找回需配置有效 SMTP。升级应用前应保留数据库备份，按既有迁移机制执行，不删除历史订单。版本发布与客户站点部署分别验收。
