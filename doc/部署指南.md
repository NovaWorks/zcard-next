# ZCard 部署指南

ZCard 以 Linux amd64 / arm64 单二进制交付，包含商城、管理后台和 SQLite 驱动。生产可使用 MySQL / PostgreSQL。不需要 PHP、额外 cron 或单独部署前端。

新安装建议使用下列一键脚本，或 Docker Compose。手动部署适合已有宝塔 / 1Panel 进程守护的服务器。首次对外开放后请立即完成安装向导。

## 方式一：Linux 一键安装

需要 Linux、Bash、curl、Python 3.9+。Debian / Ubuntu 可先安装依赖：

```bash
sudo apt update
sudo apt install -y curl python3 ca-certificates
curl -fsSL https://raw.githubusercontent.com/NovaWorks/zcard-next/main/scripts/zcard-install.sh -o /tmp/zcard-install.sh
sudo bash /tmp/zcard-install.sh install
```

脚本询问数据库类型，默认 SQLite（体验 / 轻量起步，无 Redis 依赖）；选择 MySQL / PostgreSQL 时，需准备数据库服务器与 Redis，脚本校验连接、权限，并在库不存在时尝试建库。脚本不会安装数据库服务器。

已下载二进制时可离线使用本地文件（数据库 / Redis 仍需可达）：

```bash
sudo bash /tmp/zcard-install.sh install --bin ./zcard-linux-amd64 --db sqlite
```

非交互 MySQL / PostgreSQL 示例（密码含特殊字符时用 shell 单引号）：

```bash
sudo bash /tmp/zcard-install.sh install --db postgres \
  --db-host 127.0.0.1 --db-port 5432 --db-user zcard \
  --db-pass '替换成数据库密码' --db-name zcard \
  --redis 127.0.0.1:6379 --redis-pass '替换成Redis密码'

sudo bash /tmp/zcard-install.sh install --db mysql \
  --db-host 127.0.0.1 --db-port 3306 --db-user zcard \
  --db-pass '替换成数据库密码' --db-name zcard \
  --redis 127.0.0.1:6379
```

交互输入密码时不回显；命令行参数可能被其他本机进程查看，公共服务器优先使用交互方式。无 Redis 密码时省略 `--redis-pass`。

安装步骤：

1. 下载明确 Release tag 的二进制与 `SHA256SUMS`，校验通过后才使用；`--bin` 表示信任自行提供的本地文件。
2. 生成 `/opt/zcard/configs/config.yaml` 和四把独立随机密钥，配置权限 `0600`。文件采用 JSON 形式的合法 YAML，程序正常读取。
3. 默认监听 `0.0.0.0:8000`，gRPC 默认关闭。
4. 存在 systemd 时创建 `zcard.service`，启用开机自启、启动服务，并检查 `/health`。失败以非零状态退出，不报告安装成功。
5. 浏览器打开 `http://服务器IP:8000/install`，完成管理员与站点设置。脚本预选数据库已生效；也可使用向导选择目标库。

没有 systemd 时仅准备文件并打印启动命令。**脚本不自动配置 Nginx / HTTPS，不安装 `zcard-manager` 菜单。** 旧 `deploy/install.sh` 入口会转发到同一主脚本，参数一致；请下载脚本后执行，不要 `curl | bash` 占用交互输入。

可选环境变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `ZCARD_VERSION` | `latest` | 首次下载的 Release tag，如 `v1.2.18`；不控制后续在线更新 |
| `ZCARD_PORT` | `8000` | 安装生成的 HTTP 端口，以及管理脚本健康检查端口 |
| `ZCARD_INSTALL_DIR` | `/opt/zcard` | 安装目录，使用无空格的普通绝对路径 |
| `ZCARD_GH_REPO` | `NovaWorks/zcard-next` | 首次下载来源 |

通过 sudo 使用变量时写在 sudo 后面：

```bash
sudo env ZCARD_INSTALL_DIR=/srv/zcard ZCARD_PORT=8080 \
  bash /tmp/zcard-install.sh install --db sqlite
```

自定义目录 / 端口的后续管理命令也要传相同变量。单机脚本管理固定服务名 `zcard`，不用于在同一主机安装多个实例。重复 `install` 会拒绝覆盖已有二进制或配置；升级使用 `update`。

### 服务管理与更新

```bash
systemctl status zcard
sudo systemctl restart zcard
sudo systemctl stop zcard
journalctl -u zcard -n 100 --no-pager

# 更新：复用程序内置的数据库备份、ED25519 验签、原子替换与更新状态机
sudo bash /tmp/zcard-install.sh update
# 可转发 self-update 的更新源参数
sudo bash /tmp/zcard-install.sh update -source github

# 卸载仅停止服务、取消自启并删除 unit；保留所有配置、数据和二进制
sudo bash /tmp/zcard-install.sh uninstall
```

脚本 `update` 不接受 `--bin` 裸二进制覆盖。systemd 服务使用 `Restart=always`；新版进入启动流程后，程序会对 pending 更新执行健康确认或启动失败回滚。**无法执行的新二进制、进入程序回滚逻辑前的失败等情况仍需手工恢复**，不承诺独立 OnFailure 自动回滚单元。

## 方式二：Docker Compose 一键安装

需要 Docker Engine / Docker Desktop、Docker Compose v2.20+、Git、Bash、OpenSSL、curl、Python 3。Docker 构建会下载 Node / Go 依赖，请确保网络可达。

```bash
git clone https://github.com/NovaWorks/zcard-next.git
cd zcard-next
bash deploy/docker-install.sh
```

脚本首次生成 `deploy/.env`（0600，含四把独立密钥和两个 MySQL 密码），然后构建并启动 ZCard + MySQL 8.4 + Redis 7，等待数据库与应用健康。已有 `.env` 会保留，不会重新生成密钥。镜像为本机源码构建，不依赖不存在的预发布镜像。

打开 `http://服务器IP:8000/install`：

| 向导字段 | 值 |
|---|---|
| 数据库类型 | MySQL |
| 主机 / 端口 | `mysql` / `3306` |
| 用户 / 数据库名 | `zcard` / `zcard` |
| 数据库密码 | `deploy/.env` 中 `MYSQL_PASSWORD` 的值 |
| Redis 地址 | `redis:6379` |
| Redis 密码 | 留空（仅容器内部网络，不映射公网端口） |

随后设置管理员账号、密码及站点地址。首次启动 `/health` 显示 `sqlite` 是安装向导引导库；提交 MySQL 后程序写入覆盖配置并自重启，完成后应显示 `mysql`，安装状态应为 `installed: true`。

容器内 `127.0.0.1` 指容器自身，不能作为同套 Compose 的 MySQL / Redis 地址。需 PostgreSQL 时可在向导填写容器可达的外部 PostgreSQL 地址及 Redis；默认 Compose 不附带 PostgreSQL 服务。选择 SQLite 则继续使用持久卷中的内嵌数据库。

### 配置、端口与持久化

- `deploy/.env.example` 为手工配置模板；空密钥不能启动 Compose。
- HTTP 默认映射 `0.0.0.0:8000`；可在 `.env` 修改 `ZCARD_BIND` / `ZCARD_PORT`，如主机 Nginx 反代使用 `ZCARD_BIND=127.0.0.1`。
- 不映射 gRPC、MySQL、Redis 端口；多个项目请使用不同 Compose 项目名和 HTTP 端口。
- `app-data` 卷挂载到 `/app`，进程工作目录也是 `/app`：配置在 `/app/configs`，SQLite 在 `/app/data/zcard.db`，上传在 `/app/data/uploads`，主题在数据目录内。
- `mysql-data` 卷保存 MySQL 数据，`redis-data` 卷保存启用 AOF 的 Redis 队列数据；业务密钥来自 `deploy/.env`，配置目录同时保留程序生成的配置，备份时两者都要保存。
- 自动创建的命名卷可由 UID/GID `65532:65532` 写入；自行换成 bind mount 时需先创建目录并赋予该用户写权限。

### 日常管理与升级

在仓库根目录执行（固定使用同一项目名，避免误建一套空卷）：

```bash
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs --tail 100 zcard
docker compose -f deploy/docker-compose.yml restart zcard
curl -fsS http://127.0.0.1:8000/health
```

**Docker 使用重建镜像、重建容器升级，不使用后台在线更新或容器内 `self-update`。** 二进制 `/zcard` 属于镜像，非 root 运行用户不能替换它；distroless 也没有数据库备份工具。容器重启只是重新运行已有镜像，不会自动下载新版。

升级前备份 `.env`、配置及三个数据卷，然后检出要使用的发行 tag，修改 `.env` 的 `ZCARD_VERSION` 为同一 tag，再执行：

```bash
# 先通过 git fetch --tags 和 git checkout 检出目标发行版本
bash deploy/docker-install.sh
# 重建后核对运行版本、数据库类型和安装状态
curl -fsS http://127.0.0.1:8000/health
curl -fsS http://127.0.0.1:8000/api/v1/admin/install/status
```

`ZCARD_VERSION` 只写入镜像版本信息，不会替你切换 Git 源码；两者必须一致。普通 `docker compose down` 保留命名卷；**不要对要保留数据的部署执行 `down -v` 或删除卷**。数据库迁移只前滚，回退镜像不等于回退数据库。

### Docker 备份示例

停机归档三个卷，避免运行中的 MySQL / SQLite 文件快照不一致。在仓库根目录执行；备份目录权限应为 0700：

```bash
mkdir -m 700 -p backups
cp -p deploy/.env backups/deploy.env
# 在停止前取得当前实例实际卷名，兼容自定义 Compose 项目名
app_id=$(docker compose -f deploy/docker-compose.yml ps -q zcard)
mysql_id=$(docker compose -f deploy/docker-compose.yml ps -q mysql)
redis_id=$(docker compose -f deploy/docker-compose.yml ps -q redis)
app_volume=$(docker inspect "$app_id" --format '{{range .Mounts}}{{if eq .Destination "/app"}}{{.Name}}{{end}}{{end}}')
mysql_volume=$(docker inspect "$mysql_id" --format '{{range .Mounts}}{{if eq .Destination "/var/lib/mysql"}}{{.Name}}{{end}}{{end}}')
redis_volume=$(docker inspect "$redis_id" --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}')
test -n "$app_volume" && test -n "$mysql_volume" && test -n "$redis_volume" || exit 1
docker compose -f deploy/docker-compose.yml stop
# 镜像仅用于归档，以只读方式挂载业务卷
docker run --rm -v "$app_volume:/source:ro" -v "$PWD/backups:/backup" alpine:3.20 tar czf /backup/app-data.tgz -C /source .
docker run --rm -v "$mysql_volume:/source:ro" -v "$PWD/backups:/backup" alpine:3.20 tar czf /backup/mysql-data.tgz -C /source .
docker run --rm -v "$redis_volume:/source:ro" -v "$PWD/backups:/backup" alpine:3.20 tar czf /backup/redis-data.tgz -C /source .
docker compose -f deploy/docker-compose.yml start
```

恢复需停机、使用匹配的 MySQL 版本，将归档解压到对应空卷，并恢复 `.env`；不要覆盖正在使用的数据卷。每次备份请使用不同目录，保留上一次可恢复副本。

## 方式三：手动 / 面板部署

从 [GitHub Releases](https://github.com/NovaWorks/zcard-next/releases) 下载对应架构的二进制并核对 SHA256SUMS，放到运行用户可写的目录：

```bash
mkdir -p /opt/zcard
cd /opt/zcard
cp /path/to/zcard-linux-amd64 ./zcard
chmod +x ./zcard
./zcard serve -conf configs
```

无配置时自动生成 `configs/config.yaml`（0600，含持久随机密钥），创建 SQLite 引导库。浏览器打开 `/install` 选数据库并完成安装。已有配置不会自动补密钥，旧部署请先查看文末迁移说明。

纯命令行安装可执行 `./zcard install -conf configs`，依次输入管理员用户名、密码、站点名称、站点网址；它在当前配置对应的数据库完成安装。安装后仍需 `serve` 启动服务。

宝塔 / 1Panel 的进程守护中填写：

- 启动命令：`/opt/zcard/zcard serve -conf /opt/zcard/configs`
- 运行目录：`/opt/zcard`
- 进程数：1
- 运行用户须能读写配置、数据目录及二进制所在目录（在线更新需要）。

不要同时使用 systemd 和面板守护运行同一实例。临时前台测试也可 `nohup ./zcard serve -conf configs > zcard.log 2>&1 &`，但生产应使用进程守护。

## Nginx、域名与 HTTPS

先配置 DNS 指向服务器，创建独立 Nginx 站点并转发到 ZCard HTTP 端口。宝塔 / 1Panel 可添加反向代理，目标 `http://127.0.0.1:8000`，发送原始域名。

```nginx
server {
    listen 80;
    server_name shop.example.com;
    client_max_body_size 64m;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`nginx -t` 通过后重载。HTTPS 通过面板证书功能或已安装的 `certbot --nginx -d shop.example.com` 签发，成功后再启用强制 HTTPS。不要在证书尚不存在时照抄 443 配置。API、支付回调和登录响应不能缓存。

管理后台默认 `/admin`；可调整 `server.admin_base_path` 后重启。上传 URL 前缀是 `/uploads/`，**实际文件目录是工作目录下 `data/uploads/`**。

## 密钥和数据库备份工具

新安装已自动持久化四把密钥，正常运行无需另行 export。`ZCARD_JWT_ADMIN_KEY` / `ZCARD_JWT_USER_KEY` 用于登录令牌；`ZCARD_CARD_KEY` / `ZCARD_DATA_KEY` 分别用于卡密和业务凭据加密。后两者为 32 字节 hex（64 字符），丢失后无法解密旧数据。

如果必须通过环境覆盖，systemd 脚本服务读取 `/opt/zcard/zcard.env`，格式为 `变量名=值`，文件设为 0600；面板服务在面板中设置环境变量；Docker 使用 `deploy/.env`。仅在 SSH shell 中 export **不会自动传给 systemd 服务**。使用环境覆盖时，CLI 操作也必须使用同一密钥环境；不要重新随机生成密钥来“修复”已有数据。密钥环境文件不要放入会被程序当作配置扫描的 `configs/` 目录。

SQLite 在线更新由内置备份完成。MySQL / PostgreSQL 的后台或 CLI 更新需要运行环境具备 `mysqldump` / `pg_dump`，否则备份失败会中止替换：

```bash
sudo apt install -y default-mysql-client  # MySQL
sudo apt install -y postgresql-client    # PostgreSQL
pg_dump --version
```

PostgreSQL 客户端大版本不能低于服务器版本。Debian 系脚本会尝试安装发行版提供的客户端，但不保证与外部数据库匹配；需要时按 [PostgreSQL 官方 APT 安装说明](https://www.postgresql.org/download/linux/debian/) 安装匹配版本，例如 `postgresql-client-18`。备份目录需足够空间与写权限。

## 单二进制在线更新与回滚

后台「设置 → 系统更新」或 CLI 使用同一备份、验签、原子替换流程。默认 `auto` 自动选择直连 / 加速源；也支持自建静态源。

```bash
cd /opt/zcard
./zcard self-update --check -conf configs
./zcard self-update -y -conf configs
./zcard self-update -y -conf configs -source github
./zcard self-update -y -conf configs -source static -base https://你的静态源
```

systemd 环境 CLI 会尝试自动重启；宝塔 / supervisord 的 CLI 更新后需要在面板重启。后台发起更新则按进程管理器执行重启或进程自替换。检查 `/health` 的实际版本，不以下载完成作为升级完成。

```bash
cd /opt/zcard
./zcard self-update --rollback -conf configs
sudo systemctl restart zcard
```

若新二进制本身无法执行，不能指望它执行 `--rollback`；停止服务后，从 `backups/pre-*/zcard.old` 或已验证的旧版发行文件恢复程序，再启动。只回滚程序不会恢复数据库，必要时同时恢复升级前数据库备份。保留配置和密钥。

发行侧：在 `server` 目录给 HEAD 打目标 tag 后执行 `make release`，产出双架构二进制、`SHA256SUMS`、签名 `update.json`。GitHub tag 流水线也发布这四个文件；更新签名私钥必须离线备份，不能进入 Git 或 Docker 构建上下文。

## 旧部署迁移注意事项

### 旧 SH 缺少持久密钥

旧脚本可能创建了没有 `security` 段的配置。先确认旧进程是否通过环境变量、其他配置文件或面板设置获得稳定密钥；恢复原值到持久配置后再重启。若运行中的旧进程只使用随机临时密钥，重新生成四把密钥无法恢复既有密文，**不要直接重装或重启后声称数据已修复**。先备份并在仍可解密的旧实例中完成必要的数据导出 / 迁移。

对于确认未投入使用的空实例，可备份后移走旧目录，再执行新脚本。新脚本拒绝覆盖旧部署，避免无意换钥。

### 旧 Docker 数据可能仍在容器内部

旧 Dockerfile 在 `/home/nonroot` 下写配置和数据，而卷挂在 `/data`；因此必须在删除 / 重建旧容器前停机备份：

```bash
# old-zcard 替换为已确认的旧容器名；不要先执行 down 或 rm
mkdir -m 700 -p old-zcard-backup
docker stop old-zcard
docker cp old-zcard:/home/nonroot/configs old-zcard-backup/configs
docker cp old-zcard:/home/nonroot/data old-zcard-backup/data
```

同时备份旧 `.env`、实际 MySQL / PostgreSQL 数据库和独立主题目录。将 `configs`、`data` 按相同相对路径恢复到新 `/app` 卷，确保 UID/GID `65532:65532` 可写，并沿用原密钥。若原 Compose 项目已有 `app-data` 卷，它可能是空卷或 root 所有；迁移时必须检查内容与权限，不能仅依赖新镜像自动初始化。

原 MySQL 镜像版本须先核对；本教程的新装默认 MySQL 8.4，不意味着可直接跨版本覆盖已有数据库。先在备份副本中完成恢复、登录、订单查询、卡密解密和附件访问验证，再切换线上。
