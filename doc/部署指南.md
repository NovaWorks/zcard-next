# ZCard 部署指南

## 安装方式（三选一）

### 方式一：一键安装脚本（Linux 服务器推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/NovaWorks/zcard-next/main/scripts/zcard-install.sh -o /tmp/zcard-install.sh
sudo bash /tmp/zcard-install.sh install          # 交互式：菜单选数据库（PostgreSQL 推荐/MySQL/SQLite）
# GitHub Release 页面尚未发布资产时，用本地二进制安装：
sudo bash /tmp/zcard-install.sh install --bin ./zcard-linux-amd64

# 免交互直装（数据库参数化；PG/MySQL 自动校验连接并建库，Redis 必配）：
sudo bash /tmp/zcard-install.sh install --db postgres --db-host 127.0.0.1 --db-port 5432 \
     --db-user postgres --db-pass 密码 --db-name zcard --redis 127.0.0.1:6379 [--redis-pass 密码]
sudo bash /tmp/zcard-install.sh install --db mysql    --db-host 127.0.0.1 --db-port 3306 \
     --db-user root   --db-pass 密码 --db-name zcard --redis 127.0.0.1:6379
sudo bash /tmp/zcard-install.sh install --db sqlite   # 本地测试模式（免一切依赖，含 Redis）
```

脚本自动完成：下载二进制（GitHub Releases，`ZCARD_VERSION` 可指定版本）→ 安装目录 `/opt/zcard`（`ZCARD_INSTALL_DIR` 可覆盖）→
生成配置与密钥 → **systemd 服务（开机自启 + 更新失败自动回滚）** → Nginx 站点（已装 Nginx 时自动配置 80 反代）。
SQLite 数据在 `/opt/zcard/data`。

### 方式二：手动部署 + 面板安装向导

```bash
# 1. 拿到二进制（含内嵌数据库与前端页面，单文件交付），放到部署目录
mkdir -p /opt/zcard && cd /opt/zcard && cp /path/to/zcard-linux-amd64 ./zcard && chmod +x zcard

# 2. 启动（见下文「启动与服务管理」），然后浏览器打开 http://服务器IP:8000
#    → 自动跳转安装向导 /install

# 3. 向导选数据库 → 设置管理员账号密码 + 站点名称 → 完成
```

### 方式三：CLI 安装（免浏览器）

```bash
cd /opt/zcard && ./zcard install    # 交互三问：管理员账号/密码(≥8位)/站点名/网址；全新库自动迁移
```

**无需配置 MySQL / Redis**：
- 数据库内嵌 SQLite（零依赖起步），数据文件默认在工作目录 `data/` 下
- Redis 可选——缺失时队列自动降级进程内执行
- 卡密/凭据加密密钥有安全默认（生产建议 env 注入，见下）

## 启动与服务管理

启动命令（三种安装方式通用）：

```bash
zcard serve -conf configs              # 默认全功能单进程模式（HTTP:8000 / gRPC:9000）
zcard serve -conf configs -mode all    # 同上（all 为默认）
```

- **工作目录**：必须在部署根目录（`configs/` 所在目录）启动，数据落在 `data/`、上传在 `uploads/`
- **端口**：默认 `0.0.0.0:8000`，改 `configs/config.yaml` 的 `server.http.addr`（gRPC 为 `server.grpc.addr`，置空可关闭）
- 多进程形态（可选，大规模部署）：`-mode api` 与 `-mode worker` 分进程部署；普通部署用默认 all 即可

### systemd（一键脚本安装态，推荐）

```bash
systemctl status|restart|stop zcard    # 服务名 zcard.service
journalctl -u zcard -e                 # 查看日志
zcard-manager                          # 安装脚本附带的交互管理菜单（状态/日志/重启/更新）
```

unit 特性：`Restart=always`（崩溃自动拉起）+ `OnFailure` 自动回滚单元（更新失败自动换回上一版）。

### 宝塔「进程守护管理器」

宝塔面板 → 软件商店 → 进程守护管理器 → 添加项目：

- 启动命令：`/opt/zcard/zcard serve -conf /opt/zcard/configs`
- 运行目录：`/opt/zcard`
- 进程数 1（单进程应用，勿开多进程）

### 手动 nohup（不推荐，仅临时）

```bash
nohup ./zcard serve -conf configs > zcard.log 2>&1 &
```

无管理器拉起与回滚能力，在线更新页会显示警示；建议尽快迁移到上面两种形态。

## 反向代理与域名绑定

服务默认监听 `127.0.0.1` 可达的 `:8000`，生产环境建议域名 + Nginx 反代 + HTTPS。

### 宝塔面板（推荐）

1. **建站**：网站 → 添加站点 → 域名填你的域名（纯静态，不要 PHP）
2. **反代**：站点设置 → 反向代理 → 添加，目标 URL `http://127.0.0.1:8000`，发送域名 `$host`
3. **HTTPS**：站点设置 → SSL → Let's Encrypt 一键签发 → 开启「强制 HTTPS」
4. **避坑**：站点设置 → 反向代理 → 配置文件，确认没有对 `/api` 开启缓存（或删除响应头 `Cache-Control` 的处理行）——缓存 API 响应会导致登录态/数据异常

### 手动 Nginx（完整示例）

```nginx
server {
    listen 80;
    listen 443 ssl http2;
    server_name shop.example.com;

    # HTTPS 证书（certbot 签发路径示例；只用 HTTP 可删 ssl 段）
    ssl_certificate     /etc/letsencrypt/live/shop.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/shop.example.com/privkey.pem;

    client_max_body_size 64m;          # 素材上传

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

无需 WebSocket 特殊配置（系统为常规 HTTP 轮询）；一键安装脚本已装 Nginx 时会自动写入等价配置。

### 后台安全入口（可选）

管理后台默认 `/admin`。改 `configs/config.yaml` 的 `server.admin_base_path`（如 `/my-secret-admin`）后重启生效——
自定义后原 `/admin` 不再可访问；前台入口不受影响。

## 与同类系统对比

| | ZCard | dujiao-next | acg-faka |
|---|---|---|---|
| 安装方式 | 浏览器向导（设管理员即完成） | 手编 config.yml + 管理脚本 | 浏览器向导（需填数据库） |
| 数据库 | 内嵌 SQLite，可选 MySQL/PG | SQLite | 必须 MySQL |
| Redis | 可选（自动降级） | 可选 | 无 |
| 交付形态 | 单二进制（含前端） | 二进制 + 前端目录 | PHP 目录 |

## 安装向导说明

- 未安装时：所有业务 API 自动 302 到 `/install`（Web 向导）
- 向导两步：
  - **① 选择数据库**：
    - **PostgreSQL（界面推荐·生产首选）**：完整高级能力（分站多租户/Schema 隔离/高并发）
    - **MySQL**：自托管标准形态（分站 Row 级隔离）
    - **SQLite（标注"本地测试"）**：内嵌零依赖；选择时明确提示「仅适用本地测试/功能体验，不支持分站多租户等高级功能」
    - 选 MySQL/PostgreSQL → 必填数据库连接（主机/端口/用户/密码/库名，**库不存在自动创建**）+ **Redis 必配**（SQLite 模式免 Redis）；支持「测试连接」按钮预检
    - 选 MySQL/PG 提交后：写入覆盖配置 → 服务自重启 → 在新库迁移并补装（向导轮询约 10~30 秒显示完成）
    - 切换落盘文件：`<conf目录>/database.yaml`（覆盖配置，重装可删）+ `data/.install-pending.json`（补装凭据，装完自动删）
  - **② 设置管理员**：账号密码（≥8 位，可一键生成强密码）+ 站点名称/网址
- 已安装后：`POST /api/v1/admin/install` 返回 409（幂等拒绝）；重装需清空数据库
- CLI 等价入口：`zcard install`（三问交互，SQLite 当前库直装）

## 进阶配置（可选）

需要 MySQL/PostgreSQL 或 Redis 时，改 `configs/config.yaml` 的 `data.database` / `data.redis` 段（或复制 `config.example.yaml`），**在首次运行安装向导前**配置好即可——向导检测到什么数据库就用什么。

### 数据库备份工具（PG/MySQL 必装）

在线更新在替换二进制前会**强制备份数据库**（数据安全优先，不可跳过），备份依赖系统工具：

```bash
apt install -y postgresql-client   # PostgreSQL 部署（提供 pg_dump）
apt install -y default-mysql-client # MySQL 部署（提供 mysqldump）
```

未安装时后台「系统更新」页会提前显示黄色警示；强行点更新会在备份阶段中止（磁盘零变更），
装好工具后重试即可。一键安装脚本已自动预装；SQLite 部署无需任何工具（内置备份）。

### 生产环境密钥（建议 env 注入）

```bash
export ZCARD_JWT_ADMIN_KEY=$(openssl rand -hex 32)   # 管理后台 JWT
export ZCARD_JWT_USER_KEY=$(openssl rand -hex 32)    # 前台 JWT
export ZCARD_CARD_KEY=$(openssl rand -hex 32)        # 卡密加密（换密钥=历史卡密不可解）
export ZCARD_DATA_KEY=$(openssl rand -hex 32)        # 业务凭据加密
```

⚠️ 四把密钥一经使用**不可更换**（换 = 对应加密数据不可解），请妥善保管。未配置时使用 config.yaml 兜底值；两者皆无则随机临时密钥（仅开发——重启即全部登录态失效）。

### 注意事项

- SQLite 文件路径不要放在 `-conf` 配置目录内（配置 watcher 会把库文件当配置解析）
- 升级：推荐后台「设置 → 系统更新」一键升级（自动备份 + 失败回滚，见下章）；或手动替换二进制重启（启动时自动应用增量迁移）
- 管理后台入口：`/admin`（可自定义，见「后台安全入口」）

## 在线更新（后台一键升级）

后台「设置 → 系统更新」：检查更新 → 弹窗展示 changelog → 一键更新（自动备份 DB → 下载验签 → 原子替换 → 重启）→ 页面自动刷新为新版本。

### 部署形态与更新能力对照

| 部署形态 | 更新重启方式 | 新版起不来时 |
|---|---|---|
| systemd（一键脚本安装态） | 优雅退出，Restart=always 拉起新版 | **自动回滚**上一版（OnFailure 回滚单元） |
| 宝塔「进程守护管理器」/ supervisord / pm2 | 进程自替换（exec，PID 不变，不依赖 autorestart 配置） | 手动 `zcard self-update --rollback` 后重启 |
| 裸跑 nohup | 进程自替换（exec） | **无兜底**——后台会红字警示，建议改用上两种 |

宝塔用户：把 `nohup ./zcard serve &` 换成「进程守护管理器」添加同一启动命令（见上文章节），即可获得更新失败自动重启能力。

### 更新源（大陆服务器）

默认 `auto`：探测 GitHub 直连，不通自动竞速内置加速镜像（gh-proxy.com / ghfast.top / ghproxy.net，后台可改）。
也可切换自建静态源（nginx/CDN 平铺 `update.json` + 二进制）。更新内容强制 ED25519 验签——加速镜像只可能不可用，不可能投毒。

「进程管理器」识别：默认自动探测；宝塔等环境探测不到时在「更新源配置」里手动指定（systemd / supervisord / 裸跑）。

### 发行新版本（运维侧）

```bash
cd server
git tag v1.3.0 && make release        # HEAD 必须已打 tag（防版本号落后）
# 产出 dist/：zcard-linux-amd64 / zcard-linux-arm64 / SHA256SUMS / update.json
# 上传 GitHub Release（tag=v1.3.0，四文件平铺）或静态源目录
```

签名私钥在 `server/.zcard-update-key`（已 gitignore，**离线备份**；泄露唯一处置 = genkey 换钥发新版）。

历史版本面板：`server/CHANGELOG.json`（`[{version, date, notes}]`，发版前顶部追加一条）会被 make release 自动签进 update.json——后台「系统更新」页据此渲染版本历史（验签覆盖，三源统一，无需 GitHub API）。

### 存量部署软着陆（一次性）

2026-09 前的旧构建未内嵌更新公钥（fail-closed 拒绝在线更新）。首次升级到带公钥版本：

```bash
zcard self-update -pubkey e7d28f99b52cda5e2596c4bea8b125c8c29cb4ca07af83aa5fe2a898c0e587cd -y
```

之后所有更新走后台一键或 `zcard self-update -y`，无需再传公钥。

### 手动回滚 / 灾害处置

```bash
zcard self-update --rollback          # 换回上一版二进制（zcard.prev）
systemctl restart zcard               # systemd 态；宝塔守护点重启；裸跑重新 nohup
```

更新前自动备份在二进制同目录 `backups/pre-<版本>-<时间>/`（DB dump + 旧二进制，保留最近 3 代）。
PG/MySQL 部署的备份依赖 `pg_dump` / `mysqldump`（见「数据库备份工具」小节），缺失时更新在备份阶段中止。
线上出现坏版本时发行方只能**前向修复发新版**（如 v1.3.1），绝不重指已发布的 update.json。
