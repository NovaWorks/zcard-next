# 实体商品开发与验收

开发位置：main；本功能随 v1.2.91 发布。既有 docs/plans/ 内容未修改。公开发行与客户站点部署分别验收。

## 已实现的业务规则

- 商品默认虚拟；新建时可选实体。保存后类型不可切换，避免现有库存、订单和发货方式改变语义。
- 实体仅自营快递履约，不能配置卡密、复用内容、上游代发、积分兑换，也不能从供货或抽奖入口购买。
- 实体商品及 SKU 使用数量库存。下单预占，付款不重复扣减；取消、过期或取消未发数量归还库存。已寄出的商品退款不自动补库存，须单独验收入库。
- 包邮为零；固定运费按“商品 / 订单”收取，同商品多数量、多 SKU 只收一次，不同商品相加。
- 虚拟和实体可混合购买；一单一个收货地址，可配送国家取实体商品范围交集。
- 国家联动一级地区；城市、区县、详细地址手填。姓名和电话必填，省州及邮编按目的地规则校验。地区数据随程序离线发布，不依赖实时第三方接口。
- 提交前服务端核算优惠后商品金额、运费及合计；再次提交重新验证报价。重复请求返回原订单，库存不足整体回滚。
- 订单保存地址、类型、商品名称、SKU、成交金额、运费、成本和优惠分摊快照；商品后续变更不会重算旧订单。
- 后台可按配送状态筛选，选择商品项、填写快递公司和单号发货；首版每个商品项一次发完剩余数量，可按不同商品项形成多个包裹。
- 配送状态：待付款、待发货、部分发货、已发货待收货、已收货、已取消。混合订单汇总虚拟交付和实体收货事实；仅寄出不算完成。
- 买家或管理员确认包裹收货。发货前可以同国家内更正地址；快递更正、地址更正、退款和退货入库均保留记录。
- 按订单项退款，商品金额、运费、支付手续费、取消数量分别处理。余额退款实际入账；仅取消数量且退款金额为零时无需外部退款凭证；外部渠道退款须先成功退款，再登记凭证，本次未新增自动原路退款执行器。
- 运费不参与积分、推广佣金或分站利润；商品退款按累计实际分摊扣回，事件重复或先退款后收到支付事件不会重复发奖励。已消费积分可形成退款负债。
- 游客凭查询密码查看订单地址及物流，登录用户须为订单所有人；限制跨租户操作。请求日志不记录收货地址、电话和查询密码。
- 旧商品、旧订单默认保持虚拟和旧交易版本，不重算历史金额或改变原虚拟履约口径。

## 2026-09-30 复查修复

- 混合订单取消虚拟商品时，同时释放历史 `sku_id IS NULL` 与 `sku_id = 0` 的预占卡。自动履约和上游回调再次检查取消状态，避免退款后仍交付。
- 退清整单时要求取消所有尚未交付的商品；先确定退款终态，再汇总配送进度。全部取消不再产生 `order.delivered` 事件。
- 上游采购先在订单锁内持久化采购占用，再调用外部接口；已退款或已取消项不能发起采购。采购已提交、待确认或人工核对时，阻止直接退款，需先完成采购结果核对。
- 同一订单的外部退款凭证禁止重复登记；零金额取消不占用外部退款凭证。该规则不代替支付渠道核账，也不是跨订单的全局凭证校验。
- 多次部分提现复用原有拆分行，避免唯一索引冲突；佣金扣回、提现和分站账本更新增加旧金额/旧状态校验；提现状态与金额消耗同事务提交，冲突整体回滚。
- 订单详情与交付查询共享查询密码失败锁；远端连接端口变化不能绕过锁。登录买家本人可不填查询密码查看自己的订单，仍验证租户归属。旧虚拟订单无密码的底层取货兼容行为保留。
- 实体商品有基础库存或历史无规格订单时，禁止新增首个 SKU；有 SKU 时禁止修改基础库存；SKU 有库存或历史订单时禁止删除。已有无规格订单的商品若需改为 SKU 销售，应新建商品，保证取消和退货回库位置稳定。
- 实体商品禁止导入卡密；电话号码除格式要求外，必须包含 6–15 位数字。
- 后台退款记录增加商品、运费、手续费和取消数量明细，按订单与租户过滤后分页；游客订单查询页直接显示实体收货地址与包裹进度。
- 开发计划加入 Git 跟踪例外，避免文档被通用 Markdown 忽略规则遗漏。

## 首版边界与发布注意

首版没有运费模板、按重量计费、同商品项拆包、自动快递轨迹查询、地址簿、换货或逆向快递系统。国家联动到一级地区，不承诺全球所有城市区县都有下拉数据。

上线需要同版本后端、后台和前台，先备份数据库并验证迁移，再开放实体商品销售。已产生实体订单后不能直接回滚到不识别实体商品的旧程序，应先暂停新增实体订单并评估数据及履约兼容性。数据库迁移以增量为主，不删除现有业务数据。

真实支付渠道、真实快递及外部消息投递尚未联调；本地测试、源码完成、提交发布和线上验收是不同阶段。
